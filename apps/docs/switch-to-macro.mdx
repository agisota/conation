Conation можно внедрять постепенно. Команда не обязана переносить всё в первый день: сначала подключите нужные источники, проверьте поиск и агентов, затем переносите активные рабочие материалы.

## Почта

Самый безопасный старт — подключить Gmail или Google Workspace и использовать Conation как почтовый клиент с едиными входящими.

1. Откройте **Настройки → Коннекторы**.
2. Подключите Gmail или Google Workspace.
3. Проверьте, что письма, labels и история синхронизируются.
4. Разберите входящие через Signal/Noise и горячие клавиши <kbd>j</kbd>, <kbd>k</kbd>, <kbd>e</kbd>.

Для self-host окружения не считайте JMAP/Stalwart полной заменой Gmail, пока не подтвержден end-to-end сценарий: создание mailbox, входящая доставка, отправка, синхронизация, вложения, уведомления и recovery.

## Документы

Если исходный инструмент хранит Markdown или экспортирует Markdown, перенос обычно проще: агент может прочитать страницы через коннектор и создать документы Conation.

```text
Импортируй документы из рабочего пространства "Engineering".
Сохрани структуру папок, пропусти архивные страницы и пометь спорные
места отдельным списком вопросов.
```

Для баз данных Notion заранее решите, что именно переносится как [задачи](/product/tasks), что как [CRM](/product/crm), а что как обычные документы со [свойствами](/concepts/properties).

## Каналы

Каналы Conation лучше переносить по активным темам, а не копировать весь архив старого чата.

1. Создайте канал для проекта или команды: <kbd>c</kbd> + <kbd>g</kbd>.
2. Добавьте участников по email.
3. Упоминайте документы, задачи и письма через `@`, чтобы доступ и обратные ссылки были понятными.
4. Оставьте старый чат подключенным как источник для поиска агентов, если нужен архив.

## Задачи

Для задач обычно достаточно перенести открытую работу. Закрытую историю стоит импортировать только если она реально нужна для аудита или аналитики.

```text
Найди открытые задачи в подключенном трекере по проекту Atlas.
Создай задачи Conation со статусом, приоритетом, исполнителем
и ссылкой на исходную карточку.
```

Если у команды сложный workflow, начните с базовых полей: Status, Priority, Assignees, Due Date. Дополнительные поля добавляйте через [свойства](/concepts/properties), когда станет понятно, что они действительно нужны.

## Файлы

Файлы можно переносить постепенно. Вложения из почты и каналов импортируются в файловое хранилище по мере работы, а отдельные документы и папки можно загрузить вручную.

Для production self-host проверьте объектное хранилище, backup, lifecycle policy и права доступа до массовой миграции.

## Агенты как помощники миграции

Агенты полезны для подготовительной работы: найти активные документы, сгруппировать задачи, составить карту каналов, подготовить список конфликтов и пропущенных прав.

Начинайте с режима черновика:

```text
Составь план миграции для проекта Atlas. Ничего не создавай и не меняй.
Сначала покажи список источников, рисков и данных, которые нужно проверить.
```

После проверки можно разрешать агенту создавать документы или задачи точечными запросами.

## Что не переносить автоматически

- Старые маркетинговые материалы и скриншоты прежнего бренда.
- Закрытые чаты без понятной политики доступа.
- Личные письма и файлы без явного согласия.
- Внешние CRM-данные без законного основания и retention policy.
- Исторические задачи, которые не нужны для текущей работы.

Цель перехода — чистое рабочее пространство Conation, а не механическая копия всех старых систем.
