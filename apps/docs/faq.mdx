<AccordionGroup>
  <Accordion title="Что такое Conation?">
    Conation — русскоязычное рабочее пространство для документов, сообщений,
    задач, файлов, почты и AI-инструментов. Сущности представлены блоками,
    которые можно связывать через @mention, искать и открывать рядом.

    Проект создаётся как white-label форк Macro. Пользовательский бренд —
    Conation; технические контракты upstream изменяются только там, где это
    безопасно или сопровождается миграцией.

  </Accordion>

<Accordion title="Conation работает в браузере или только как desktop-приложение?">
  Работает в браузере. Основной интерфейс — SolidJS/Vite SPA, локально доступный
  по адресу `http://localhost:3000/app`. Tauri упаковывает тот же клиент в
  нативную оболочку. Подписанный публичный desktop-релиз и production web-домен
  пока не подтверждены.
</Accordion>

<Accordion title="Все функции Conation бесплатны?">
  Да, Conation не делит пользователей и команды по продуктовым тарифам и не
  требует платных мест. При этом инфраструктура и внешние сервисы не становятся
  бесплатными: оператор оплачивает серверы, домен, хранение, резервные копии,
  почтовую доставку и используемые API AI/GitHub/Google.
</Accordion>

  <Accordion title="Можно ли развернуть Conation самостоятельно?">
    Репозиторий предоставляет локальный single-host контур для разработки,
    оценки и smoke-тестов. Он поднимает Postgres/pgvector, Redis, OpenSearch,
    Kafka, FusionAuth, LocalStack, Mailpit, frontend, API и workers через
    репозиторные скрипты.

    Это ещё не поддерживаемый Internet-facing production-дистрибутив. Не
    завершены полная замена AWS-контрактов, hardening ingress, multi-node
    topology, проверенный backup/restore, production mail delivery, signed
    desktop release и end-to-end проверка публичных OAuth/MCP endpoints.

  </Accordion>

  <Accordion title="Что означает профиль standalone?">
    `standalone` — профиль адресации клиента. Production web-сборка использует
    same-origin API и не должна незаметно обращаться к управляемым endpoint
    Macro. Оператор обязан направить нужные пути на собственные сервисы.

    Профиль не создаёт серверы, DNS, TLS, OAuth credentials и резервные копии.
    Поэтому standalone-артефакт — необходимая часть независимого развёртывания,
    но не доказательство его production-готовности.

  </Accordion>

  <Accordion title="Почему в коде ещё встречаются macrodb, macro_user или MacroUserId?">
    Это внутренние или persisted identifiers: имена схемы, колонок, типов,
    переменных и volumes. Простая замена может сломать существующую базу,
    SQLx-кэш, API payload, token или поиск ресурса при обновлении.

    Пользовательский бренд от них не зависит. В greenfield-профиле новые
    пользовательские идентификаторы используют namespace `conation|`.
    Переименование долговечных контрактов выполняется отдельными миграциями, а
    не текстовой заменой.

  </Accordion>

  <Accordion title="Есть ли у Conation собственные почтовые ящики?">
    Пока приложение не использует Stalwart как полноценный backend
    пользовательской почты. Репозиторий умеет подготовить Stalwart и создать
    служебные ящики после явного запуска оператором, но JMAP sync, cursors,
    outbound delivery и подключение web inbox ещё не завершены.

    Рабочий inbox сейчас требует Gmail или Google Workspace с OAuth credentials
    вашего оператора. Mailpit в локальном контуре принимает транзакционные
    письма, но не заменяет пользовательский почтовый сервер.

  </Accordion>

<Accordion title="Можно ли не подключать Gmail?">
  Да, если вам не нужен почтовый блок: документы, каналы, задачи и другие
  доступные сервисы можно проверять отдельно. Но до завершения JMAP-адаптера
  отказ от Gmail означает, что полноценный пользовательский inbox в Conation
  недоступен.
</Accordion>

  <Accordion title="Как работают AI-агенты?">
    Код поддерживает агентские сценарии и MCP-инструменты. Для реальных ответов
    оператор должен настроить совместимый модельный endpoint и сервисный ключ.
    Наличие названия модели в конфигурации не доказывает работоспособность
    автоматического fallback: его нужно проверять end-to-end для выбранного
    gateway.

    Агент наследует разрешения пользователя. Данные, отправленные внешнему
    модельному или MCP-провайдеру, обрабатываются по условиям этого провайдера.

  </Accordion>

<Accordion title="GitHub и MCP готовы без дополнительной настройки?">
  Нет. Исходный код содержит соответствующие сервисы и маршруты, но оператору
  нужны собственные OAuth/App credentials, точные callback URLs, TLS и ingress.
  Публичные точки на `conation.dev` этой документацией не считаются
  проверенными. См. [«GitHub»](/integrations/github) и [«Настройка
  MCP»](/AI/mcp/overview).
</Accordion>

  <Accordion title="Как Conation использует мои данные?">
    В self-hosted режиме правила хранения, доступа, журналирования и передачи
    данных определяет оператор. Подключая Gmail, GitHub, AI или внешний MCP,
    оператор и пользователь передают данные соответствующему провайдеру.

    Не переносите на Conation обещания прежнего hosted Macro о сертификации,
    регионе или zero-retention без отдельного договора и технической проверки.
    Практические требования перечислены в разделе
    [«Безопасность»](/security).

  </Accordion>
