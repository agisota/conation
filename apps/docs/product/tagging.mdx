Тег — это [свойство](/concepts/properties), доступное разным типам блоков. Один namespace тегов работает для документов, писем, задач, чатов, звонков и других объектов Conation.

Теги подходят для группировки работы по проекту, команде или области: например `marketing`, `hiring`, `q3-launch`. Для статуса, приоритета и исполнителя лучше использовать отдельные свойства.

<Note>
  Старые скриншоты прежнего интерфейса убраны из активной страницы. Новые
  изображения тегов должны быть сняты в Conation на синтетических данных.
</Note>

## Что можно тегировать

- **Документы** — Markdown-документы, PDF, изображения, видео, code-файлы и [snippets](/product/snippets).
- **Письма** — цепочки и отдельные email-блоки.
- **Задачи** — чтобы группировать работу с похожим контекстом.
- **AI-чаты** — чтобы позже вернуться к важной сессии агента.
- **Звонки** — чтобы связать обсуждения с проектом или клиентом.

## Создание тегов

Откройте панель свойств у блока, добавьте свойство Tags и введите название нового тега. Если тег уже существует, Conation предложит выбрать его из списка.

Цвет тега помогает визуально отличать группы, но не влияет на поиск или права доступа.

## Поиск по тегам

Откройте [поиск](/product/search), включите фильтр **Tags** и выберите нужные теги. Для нескольких тегов можно искать объекты, где есть любой выбранный тег, или только объекты со всеми выбранными тегами.

## Рекомендации

- Используйте короткие названия тегов.
- Не дублируйте статус тегами вроде `done` или `urgent`, если уже есть системные свойства.
- Договоритесь с командой о базовом наборе тегов для проектов и клиентов.
