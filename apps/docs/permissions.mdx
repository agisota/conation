Conation использует несколько уровней доступа: прямой sharing объекта, участие в канале, командные правила и системные права конкретного блока.

<Note>
  Старая диаграмма прежнего интерфейса убрана из активной страницы. Новую схему
  прав нужно подготовить отдельно для Conation и self-host сценариев.
</Note>

## Sharing через каналы

Когда объект упоминают в канале, доступ может быть выдан участникам канала автоматически. Если человека добавляют в канал, он получает доступ к объектам, расшаренным через этот канал. Если человека удаляют, этот доступ должен быть отозван по правилам модели доступа.

Такой подход уменьшает количество ручных запросов «поделись документом», но требует аккуратной настройки каналов.

## Общие правила уведомлений

Пользователь получает уведомление во входящих только если у него есть доступ к соответствующему объекту.

Упоминание в теле Markdown-документа или задачи не обязательно создает уведомление. Упоминание в thread-контейнере, например комментарии или сообщения, создает уведомление.

## Документы

Уведомления по документу появляются после явного sharing или после упоминания в комментарии. Упоминание человека в теле документа не должно автоматически уведомлять его.

Public link делает документ доступным любому, у кого есть ссылка. Перед включением public link проверьте чувствительность содержимого и требования [безопасности](/security).

## Задачи

Задачи могут попадать в командную память по умолчанию. Участники команды видят задачи согласно своим ролям и настройкам доступа.

Назначение пользователя исполнителем создает уведомление. Упоминание человека в теле задачи не обязано уведомлять; упоминание в комментарии — уведомляет.

## Каналы

Участника можно добавить в канал по email. Если у него еще нет аккаунта, приглашение или уведомление отправляется через настроенный почтовый канал.

`@here` уведомляет весь канал, `@user` — одного пользователя, `@Conation` вызывает агента внутри канала.

Участников можно добавлять и удалять через participants tab канала.

## Звонки

Командный звонок может попадать в Calls tab и командную память вместе с записью, расшифровкой и AI-summary. Если звонок не должен быть общим, отключите sharing до или во время звонка.

Для production self-host заранее проверьте политику хранения записей, доступ к расшифровкам, backup и требования законодательства.
