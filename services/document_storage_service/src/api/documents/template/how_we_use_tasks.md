# Пример процесса с задачами

Это учебный пример, а не описание обязательного процесса вашей команды.

Работа может начаться с сообщения об ошибке в канале. Из сообщения создают задачу через `/task` или действие «Задача» в меню сообщения. Между исходным обсуждением и задачей сохраняется двусторонняя ссылка, поэтому контекст легко восстановить.

Если в развертывании подключена почта, задачу можно создать и из письма службы поддержки. Назначенные вам задачи появляются во входящих вместе с другими доступными источниками уведомлений.

Для объёмного описания функции подготовьте документ, затем попросите **@conation** составить из него задачи. Помощник действует только в пределах предоставленных ему прав и доступного контекста; создание и назначение задач зависит от включённых инструментов агента.

Если настроена интеграция с GitHub, задача может быть связана с веткой и pull request, а её статус — обновляться по мере разработки и ревью.

Главная идея процесса — связать исходное обсуждение, документ, задачу и pull request. Тогда участникам не приходится вручную переносить контекст между разными местами.
