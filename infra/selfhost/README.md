# Статус самостоятельного развёртывания Conation

Conation поддерживает **локальную, однохостовую базовую конфигурацию без
управляемого облака** для разработки, оценки и проверочных тестов оператора.
Поддерживаемой дистрибуции для рабочего развёртывания с доступом из Интернета
пока нет. Стеки Pulumi для рабочего окружения остаются привязанными к AWS.

Это различие существенно: локальная базовая конфигурация запускает продукт в
контейнерах и с эмуляцией AWS API, тогда как самостоятельному развёртыванию для
рабочего окружения всё ещё требуются границы провайдера, усиление защиты,
проверка резервного копирования/восстановления и контракт обновлений.

## Поддерживаемая базовая конфигурация

Nix — единственное требование к хосту. Docker, Compose, `just`, Rust и
инструменты фронтенда поставляются закреплённой средой разработки. Из корня
репозитория выполните:

```bash
bash .cursor/infra.sh
bash .cursor/stack.sh
```

`stack.sh` сам вызывает `infra.sh`, поэтому для полного запуска достаточно
второй команды. Отдельный запуск `infra.sh` полезен перед тестами, которым нужна
БД. Ни одна из команд не сбрасывает исправно работающий стек. Не передавайте
`--fresh`, если потеря данных локального стека не является намеренной.

Эквивалентные обёртки репозитория:

```bash
nix develop --command just selfhost-infra
nix develop --command just selfhost-up
nix develop --command just selfhost-status --json
```

После изменения бэкенда выполните:

```bash
bash .cursor/rebuild.sh
```

Изменения фронтенда применяются через горячую перезагрузку. Чтобы остановить
контейнеры и сохранить тома, выполните:

```bash
nix develop --command just selfhost-down
```

Стандартные конечные точки: приложение на `http://localhost:3000/app`, прокси
бэкенда на `http://localhost:8090`, FusionAuth на `http://localhost:9011`,
Mailpit на `http://localhost:8025` и LocalStack на `http://localhost:4566`.

### Автономные веб- и нативные клиенты

Веб-сборка для рабочего окружения по умолчанию использует клиентский профиль
`standalone`. Он выводит каждый API приложения из адреса, с которого отдаётся
страница, и не переключается на управляемый сервис `macro.com`:

```bash
cd apps/web
bunx vite build -c vite.config.ts
```

Задайте `VITE_CONATION_OPERATOR_ORIGIN=https://conation.example`, чтобы
привязать веб-артефакт к одному базовому адресу оператора, либо оставьте
значение для рабочего окружения по умолчанию `same-origin`, чтобы один и тот же
артефакт следовал адресу, с которого он отдаётся. Контракт входящего трафика
для автономного режима включает `/auth`, `/app/login`, `/pdf`, `/dss`,
`/websocket`, `/cognition`, `/connection-gateway`, `/notification`,
`/static-file`, `/unfurl`, `/contacts`, `/email`, `/image-proxy`,
`/scheduled-action`, `/agent-harness`, `/sync`, `/mcp`, `/ai-editing` и
`/i/ph`. Клиенты WebSocket используют `ws:`/`wss:` с тем же хостом и путём
`/websocket`, `/connection-gateway` или `/sync`. Оператор должен
маршрутизировать каждый включённый путь; отсутствие маршрута приводит к отказу
только соответствующей функции, а не к перенаправлению трафика в инфраструктуру
Macro.

Карты исходников для автономного режима по умолчанию выключены: благодаря
этому обычная сборка Vite остаётся ниже наблюдаемого пика использования кучи
Node. Задавайте `VITE_CONATION_SOURCEMAPS=true` только если оператор владеет
получающимися картами.

Релизные нативные сборки используют тот же профиль и по умолчанию обращаются к
`https://conation.dev`:

```bash
cd apps/web
CONATION_OPERATOR_ORIGIN=https://conation.example just tauri-build-standalone
```

`CONATION_BUNDLE_UPDATE_BASE_URL` при необходимости выбирает отдельную
принадлежащую оператору конечную точку OTA-пакета; по умолчанию это
`<operator-origin>/auth/`. `CONATION_TAURI_HTTP_ORIGINS` — необязательный
разделённый запятыми список дополнительных базовых адресов, необходимых для
прямых URL объектов. Сборка проверяет все эти значения как корневые
HTTP(S)-адреса и отклоняет управляемые хосты Macro. Она компилирует точный хост
оператора в возможность Tauri HTTP и список разрешённых универсальных ссылок;
пользовательские домены должны публиковать соответствующие метаданные
ассоциации Apple/Android. Автономные пользовательские URL используют
`conation://`.

Это топология для разработки, а не защищённый межсетевой экран хоста. Несколько
портов базовых сервисов приложения намеренно сохраняют привязку Docker ко всем
интерфейсам для существующих локальных/мобильных сценариев. Запускайте её только
на доверенной машине за межсетевым экраном и не публикуйте эти порты в
Интернете. Экспериментальное дополнение ниже независимо проверяется как
доступное только на loopback; дистрибутив с доступом из Интернета также должен
сделать базовую конфигурацию только входной и убрать прямые привязки сервисов.

### Строгий профиль URL сервисов (экспериментальный)

`CONATION_SERVICE_URL_PROFILE=strict-self-host` — явный opt-in для проверки,
что код, использующий типизированные URL сервисов, не молча возьмёт managed
default. Он **не** делает самостоятельное развёртывание production-ready и не
настраивает Compose, ingress, DNS, TLS, секреты или маршруты. Рабочее
развёртывание с доступом из Интернета остаётся неподдерживаемым.

Скопируйте [`strict-service-urls.env.example`](./strict-service-urls.env.example)
в принадлежащее оператору secret/config store и замените все placeholder DNS
имена. Это не готовый `.env`: шаблон намеренно содержит не секреты, а
неработающие без собственных ingress-маршрутов адреса. В нём перечислены все 19
нынешних `OVERRIDE_*` URL-переменных. Для HTTP(S) сервисов он использует
ожидаемые same-origin path prefixes: `/auth`, `/pdf`, `/dss`,
`/connection-gateway`, `/cognition`, `/notification`, `/static-file`,
`/agent-harness`, `/unfurl`, `/contacts`, `/email`, `/image-proxy`, `/lexical`
и `/ai-editing`; WebSocket endpoints используют `/websocket`,
`/connection-gateway` и `/sync`. Оператор обязан реализовать и проверить каждый
из этих маршрутов. `OVERRIDE_AGENT_PROXY_WEBSOCKET_URL` также обязателен для
полного шаблона, хотя локальный ingress не публикует такой маршрут и сам endpoint
сейчас не используется.

При `strict-self-host` каждый разрешаемый URL требует соответствующий
`OVERRIDE_*`; отсутствие значения — ошибка запуска вместо fallback на managed
host. Значение должно быть абсолютным URL с host: HTTP-службы принимают только
`http`/`https`, WebSocket-службы — только `ws`/`wss`. Проверка отклоняет userinfo,
query, fragment, а также `macro.com`, любой его subdomain, `macroverse.workers.dev`
и его subdomain. Принимаемый path prefix не доказывает, что ingress действительно
маршрутизирует запрос: это отдельная обязанность оператора.

Допустимы только значения профиля `managed` и `strict-self-host`; unset равен
`managed`. Откат профиля — удалить `CONATION_SERVICE_URL_PROFILE` либо задать
`managed`, затем перезапустить все затронутые процессы. В `managed` существующие
`OVERRIDE_*` остаются активными; чтобы вернуться именно к environment defaults,
удалите и overrides. Эти defaults могут вести в managed-инфраструктуру, поэтому
не используйте такой откат как подтверждение работоспособного production пути.

## Базовая топология

| Возможность | Локальный компонент | Состояние и ответственность |
| --- | --- | --- |
| Основные реляционные данные | PostgreSQL 18 + pgvector, база данных `macrodb` | Постоянный том Docker; `macrodb` остаётся именем для совместимости |
| Кэш и временное состояние | Redis Stack | Постоянный том в локальном стеке, однако Redis по-прежнему следует считать восстанавливаемым состоянием кэша |
| Поиск | OpenSearch | Локальный постоянный том; схемы индексов инициализируются оркестратором стека |
| Поток событий | Одноузловой Kafka/KRaft | Локальный постоянный том; это не отказоустойчивая топология Kafka |
| S3, SQS, DynamoDB, KMS APIs | LocalStack | Эмуляция с фиктивными учётными данными, подготовленная из общего каталога локальных ресурсов |
| Аутентификация | FusionAuth | Самостоятельно размещённый контейнер со сгенерированной локальной kickstart-конфигурацией |
| Перехват транзакционной почты | Mailpit SMTP/UI | Безопасный локальный приёмник; не доставка почты через Интернет и не провайдер пользовательского почтового ящика |
| HTTP-маршрутизация | Сгенерированный прокси Caddy | Маршрутизация сервисов от одного базового адреса на порту 8090; стеки без UI также могут отдавать собранный фронтенд |
| Публичный MCP | `mcp_service` за сгенерированным Caddy | `/mcp` перенаправляется без удаления префикса; обнаружение OAuth, `/authorize`, `/register`, `/token` и `/oauth/callback` используют базовый адрес прокси. У сервиса нет прямого хостового порта |
| Фронтенд | Сервер разработки Vite/SolidJS | Приложение с горячей перезагрузкой на порту 3000 в сценарии Cursor |
| API приложения и воркеры | Контейнеры Rust/TypeScript, собранные из репозитория | Собираются и оркестрируются `xtask_local`; отказавшие необязательные интеграции видны в статусе/логах сервисов |
| Запланированные автоматизации | API `scheduled_action_service` + диспетчер PostgreSQL с опросом | Включены в полный локальный стек; доступны через прокси по `/scheduled-action` и напрямую на порту `8103` для локальной диагностики |

Сгенерированный стек отвечает за создание сети, томов, создание и миграции баз
данных, kickstart FusionAuth, ресурсы LocalStack, схемы OpenSearch, темы
Kafka, маршруты прокси и отчёт о работоспособности сервисов. Рецепты
самостоятельного развёртывания не реализуют эти операции повторно.

Чистый профиль Conation использует тома Docker `conation_postgres_data`,
`conation_redis_data`, `conation_opensearch_data` и `conation_kafka_data`.
Инструментарий никогда не принимает, не переименовывает и не удаляет устаревшие
тома `macro_*` автоматически; перед переходом на другой том оператор должен
явно проверить и мигрировать данные.

## Карта зависимостей AWS

Исходное дерево всё ещё содержит клиентов AWS SDK для S3, SQS, DynamoDB, KMS,
SESv2, SNS, Secrets Manager, Lambda, ECS и STS. Их текущий статус при
самостоятельном развёртывании явно указан ниже.

| Зависимость AWS | Решение для базовой конфигурации | Статус самостоятельного развёртывания для рабочего окружения |
| --- | --- | --- |
| S3 | Эмулируется LocalStack | MinIO — возможный целевой вариант, но не подключён; см. ограничение конечной точки ниже |
| SQS | Эмулируется LocalStack; локальные потребители очереди работают в контейнерах | Независимый от брокера адаптер долговечной очереди и операции повторных попыток/DLQ для рабочего окружения не определены |
| DynamoDB | Эмулируется LocalStack | Нет адаптера для рабочего окружения без AWS; резервное копирование/восстановление таблиц не определено |
| KMS | Эмулируется LocalStack для локальных потоков шифрования ключей | Требуются решение по управлению ключами/HSM для рабочего окружения и процедура ротации/восстановления ключей |
| SESv2 | Некоторые транзакционные пути выбирают SMTP и доставляют в Mailpit | Прямые адаптеры SES и доставка через Интернет заменены не полностью |
| SNS/mobile push | Не включены в базовую конфигурацию LocalStack | Жизненный цикл конечных точек APNS/FCM и доставка push остаются неподдерживаемыми |
| Secrets Manager | Не включён в базовую конфигурацию LocalStack | Должен быть заменён принадлежащими оператору хранилищем секретов и адаптером |
| Lambda | Для подмножества обработчиков событий есть локальные эквиваленты в виде длительно работающих воркеров | Оставшиеся триггеры Lambda, повторные попытки, параллельность и расписания не поддерживаются |
| ECS | Нет замены для рабочего окружения | Размещение и жизненный цикл задач, запускаемых воркерами, не поддерживаются |
| STS | Статические фиктивные локальные учётные данные исключают обычный поиск учётных данных | Идентификация рабочих нагрузок для рабочего окружения не спроектирована |
| CloudFront/ALB | Обходятся сгенерированными локальными маршрутами Caddy/static-file | Публичный TLS, кэширование CDN, эквивалентность подписанных URL, WAF и многоузловая входящая маршрутизация не поддерживаются |
| EventBridge/запланированные задания | Созданные пользователями автоматизации Conation работают в `scheduled_action_service`; его диспетчер PostgreSQL атомарно захватывает строки, срок которых наступил | Более широкий перечень устаревших расписаний AWS, политика пропущенных запусков и многоузловые операции для рабочего окружения остаются незавершёнными |

Концепции RDS/pgvector, ElastiCache, Amazon OpenSearch и MSK уже имеют
локальные замены в виде PostgreSQL, Redis, OpenSearch и Kafka. Само по себе это
не предоставляет отказоустойчивость, шифрование, мониторинг или аварийное
восстановление для рабочего окружения.

### События объектного хранилища

Поддерживаемый локальный оркестратор создаёт bucket `doc-storage` и связывает
его события `ObjectCreated` с очередью SQS document-upload-finalizer.
`document_upload_finalizer_local_worker` потребляет эту очередь. Другие потоки
S3-to-Lambda для рабочего окружения заменены не исчерпывающим образом.

Сейчас приложение использует один `LOCAL_AWS_URL` для всех клиентов AWS SDK.
Если указать в нём MinIO, вызовы SQS, DynamoDB и KMS также будут направлены в
MinIO. Поэтому экспериментальный файл Compose запускает MinIO только как
изолированную цель совместимости и не переопределяет сервисы приложения.
Реальный переход на MinIO требует конфигурации конечной точки для каждого
сервиса, а также тестов предварительно подписанных URL и доставки событий.

### Почта

Регистрация создаёт пользовательский ящик Stalwart и link
`UserProvider::Stalwart`. На этом дереве JMAP читает тело письма, флаги и
вложения и отправляет сообщения. Gmail — необязательная внешняя интеграция,
а не единственный inbox веб-почты.

Поддерживаемая базовая конфигурация направляет транзакционные SMTP-пути в
Mailpit. Это локальный приёмник системных писем, а не доставка через
Интернет и не замена пользовательского ящика. Публичные MX, DKIM и
сопутствующая internet-доставляемость не поддерживаются.

MinIO по умолчанию не подключён как S3 приложения: клиенты AWS SDK
ходят в LocalStack через `LOCAL_AWS_URL`. Явный `S3_ENDPOINT_URL`
изолирует только S3 (например MinIO) и не перенаправляет SQS/DynamoDB/KMS.
Без этой переменной указывать MinIO в `LOCAL_AWS_URL` нельзя.

После завершения начальной инициализации оператором явный протестированный
рецепт может создать домен `conation.dev` и три фиксированных почтовых ящика
поддержки без сброса существующих паролей:

```bash
nix develop --command just selfhost-provision-support-mailboxes
```

Образ сервера не содержит CLI; рецепт запускает отдельный официальный образ
Stalwart CLI, закреплённый digest. См.
`docs/SELF_HOST_STALWART_MAILBOX_AUDIT_RU.md` для трассировки провайдера,
контракта секретов, контрольного списка DNS/доставляемости и точной границы
неподдерживаемого. Пользовательская конфигурация Stalwart для рабочего
окружения пока не поставляется и не монтируется.

## Экспериментальное дополнение

`docker/docker-compose.selfhost.yml` сохраняет MinIO, Stalwart, LocalStack и
локальный фасад Caddy для ограниченных интеграционных работ. Это отдельное
определение дополнения, а не второй запускатель приложения; для него нет
рецепта `up`. Проверить его можно без затрагивания работающих контейнеров:

```bash
nix develop --command just selfhost-overlay-check
```

Проверка использует отслеживаемый `.env.selfhost.example`; ей никогда не нужно
читать игнорируемый `.env.selfhost` с секретами. Она собирает только файл
дополнения, отклоняет унаследованные сервисы приложения, отклоняет каждый
опубликованный порт вне loopback и требует, чтобы каждая ссылка на образ
содержала неизменяемый digest. Фасад Caddy использует обычный HTTP и направляет
трафик приложения на поддерживаемый прокси на порту 8090. Его стандартные
конечные точки:

- `http://localhost:8088/app` с `Host: conation.localhost`
- API/UI MinIO на портах 9000/9001
- JMAP/bootstrap UI Stalwart на порту 18081
- SMTP/submission/IMAPS Stalwart на портах 2525/2587/2993

Эти порты настраиваются и по умолчанию привязаны к `127.0.0.1`. Проверка
безопасно отклоняет конфигурацию, если файл окружения меняет адрес привязки на
`0.0.0.0` (или любой другой адрес вне loopback).

Образы дополнения закреплены одновременно читаемым тегом и digest реестра:
сервер MinIO `RELEASE.2025-09-07T16-13-09Z`, клиент MinIO
`RELEASE.2025-08-13T08-35-41Z`, Stalwart `v0.16` и Caddy `2.11.4-alpine`.
Тег основной версии LocalStack также закреплён digest. Обновление любого такого
закрепления требует проверки конфигурации и соответствующих тестов
работоспособности/интеграции; изменяющийся тег `latest` не принимается.

## Владение секретами и конфигурацией

## Coding agent: граница self-host

Официальный `agent_harness_service` входит в локальный/self-host stack. В
local-режиме он использует управляемый Docker sandbox, а при настройке Daytona
— управляемый Daytona sandbox. Доступ к моделям проходит через ограниченный
server-side egress с session capability; `ROX_API_KEY` не передаётся в sandbox.

Это не означает, что все агенты репозитория готовы к самостоятельному
развёртыванию. Rust `conationd` остаётся доверенным daemon оператора вне stack:
размещение OpenCode рядом с его bot/webhook конфигурацией без сильной изоляции
процесса раскроет операторские секреты. Отдельный TypeScript
`coding-agent-worker` рассчитан на Daytona/cloud, пока не имеет
воспроизводимого self-host image и host routing; его GitHub credential всё ещё
видим процессам sandbox.

Перед production нужны scoped internal egress grant либо GitHub API proxy,
изоляция секретов/процессов, публичные TLS endpoints и callbacks, а затем
реальные session/completion smoke-тесты. До этого self-host stack пригоден для
локальной разработки и smoke-проверок, а не для заявления production-ready
coding agent.

- Локальная базовая конфигурация генерирует детерминированные служебные
  настройки для нерабочего окружения и фиктивные учётные данные AWS в
  `xtask_local`.
- `DOPPLER_TOKEN` (или `DOPPLER_PREVIEW_TOKEN`) необязателен. Когда он задан,
  скрипт Cursor читает конфигурацию `local/lcl_preview`; без него стек
  использует локальные заглушки. Передавайте токен как секрет окружения, никогда
  не помещая его в отслеживаемый файл или чат.
- `NIX_CACHE_AWS_ACCESS_KEY_ID` и `NIX_CACHE_AWS_SECRET_ACCESS_KEY` —
  необязательные учётные данные только для чтения из приватного кэша Nix.
  Сборки из исходного кода работают и без них, но занимают больше времени.
- Для сборки приватного пакета может потребоваться `GITHUB_PACKAGES_TOKEN`;
  храните его в окружении процесса или хранилище секретов оператора.
- Скопированный `.env.selfhost` владеет только экспериментальными учётными
  данными MinIO/Stalwart и интерполяцией порта/домена. Это не перечень секретов
  приложения для рабочего окружения.
- Провайдеры AI и OAuth, биллинг, мобильные push-уведомления и внешние
  соединители остаются интеграциями, которые выбирает оператор. Их учётные
  данные не являются частью ядра без управляемого облака и должны отсутствовать
  при отключении функции.

Перед поддержкой рабочего окружения у каждой обязательной переменной должен
быть владелец, политика ротации, проверка при запуске и редактированная
диагностика. Приложение обязано использовать свои типизированные макросы
окружения; работа по развёртыванию не должна вводить произвольные чтения
`std::env::var` в Rust.

## Проверка работоспособности

После завершения `bash .cursor/stack.sh` выполните:

```bash
nix develop --command just stack status --json
curl -fsS http://localhost:8090/auth/health
curl -fsS http://localhost:8090/scheduled-action/health
curl -fsS http://localhost:8090/.well-known/oauth-protected-resource/mcp
test "$(curl -sS -o /dev/null -w '%{http_code}' http://localhost:8090/mcp)" = 401
curl -fsS http://localhost:4566/_localstack/health
curl -fsSI http://localhost:3000/app
```

Затем откройте `http://localhost:3000/app`, запросите вход без пароля, получите
код из `http://localhost:8025`, войдите, загрузите небольшой документ и
подтвердите, что его можно открыть повторно. Если индексация не завершается,
проверьте воркер upload-finalizer и search service в `just stack status`.

Сгенерированное локальное окружение задаёт `MCP_PUBLIC_URL` равным базовому
адресу прокси (`http://localhost:8090` для экземпляра по умолчанию), а kickstart
FusionAuth регистрирует соответствующий точный адрес обратного вызова
`http://localhost:8090/oauth/callback`. Именованные экземпляры используют свой
вычисленный порт прокси. Только локальный процесс дополнительно принимает
точный внутренний authority `mcp-service:8080`, используемый исходящими
запросами агента; развёрнутые окружения этот authority не добавляют.
Развёртывание в Интернете по-прежнему требует принадлежащих оператору DNS/TLS и
адреса обратного вызова для рабочего окружения, описанного в
`docs/CONATION_INTEGRATIONS_RU.md`.

Экспериментальные дополнения можно проверять независимо, когда они уже
запущены:

```bash
curl -fsS http://localhost:9000/minio/health/live
curl -fsS http://localhost:18081/ >/dev/null
```

Исправный контейнер MinIO или Stalwart не доказывает, что приложение его
использует.

## Обновления, резервное копирование и восстановление

`bash .cursor/rebuild.sh` обновляет бинарные файлы бэкенда без очистки томов.
Снимки инициализации локального стека — артефакты ускорения, а не резервные копии
оператора.

`just selfhost-backup /absolute/path/outside/the/repository` создаёт только
PostgreSQL-дамп `macrodb` с ограничительными правами доступа к файлу. Рецепт
отклоняет относительные и канонически расположенные внутри репозитория места
назначения, включая пути, перенаправленные в рабочую копию символической
ссылкой, поэтому экспорт БД не может попасть в снимок исходного кода.
Поддерживается ещё не созданная директория вне рабочей копии. Неудачные дампы
удаляют свой приватный временный файл; успешные дампы атомарно публикуются под
именами, защищёнными от коллизий. Рецепт намеренно сообщает, что эта копия
неполна. Для плана
восстановления рабочего окружения всё ещё нужны согласованные версионированные
копии PostgreSQL, объектного хранилища, FusionAuth, Kafka и OpenSearch; Redis должен
быть восстанавливаемым.
Порядок восстановления, согласованность на момент времени, шифрование,
хранение вне хоста и регулярная проверка восстановления не реализованы.

Наблюдаемость также ограничена локальным режимом. Jaeger можно включить для
трассировки, но поддерживаемого набора метрик/логов/оповещений/SLO для рабочего
окружения нет.

## Критерии готовности к рабочему окружению

Не объявляйте развёртывание с доступом из Интернета поддерживаемым, пока не
будут выполнены все условия ниже:

1. Разделить конечные точки AWS по возможностям и проверить MinIO вместе с
   событиями объектов.
2. Реализовать и протестировать провайдер Stalwart/JMAP от начала до конца либо
   явно не предоставлять размещение почтового ящика и использовать
   протестированное SMTP-реле для транзакционной почты.
3. Заменить или формально исключить SNS, Secrets Manager, Lambda, ECS,
   устаревшие расписания вне `scheduled_action_service` и каждый оставшийся
   прямой путь клиента AWS.
4. Определить контракты совместимости для TLS, DNS, обратного вызова OAuth,
   CORS, подписанных ссылок и публичного входящего доступа.
5. Закрепить оставшиеся образы/артефакты базового стека и опубликовать
   миграции, процедуры пошагового развёртывания/отката, размеры ресурсов,
   проверки работоспособности/готовности и окно поддержки обновлений.
6. Завершить резервное копирование/восстановление, восстановление ключей,
   мониторинг и усиление безопасности; протестировать их на чистом хосте.
7. Выполнить функциональные проверочные тесты и тесты отказов/восстановления
   без каких-либо управляемых учётных данных AWS в окружении.

Репозиторий лицензирован по AGPLv3. Операторы, которые изменяют его и
предоставляют сетевой доступ, должны учитывать обязательства лицензии по
предоставлению соответствующего исходного кода.
