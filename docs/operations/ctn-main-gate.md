# Local main backup and recovery

This procedure implements the current RUS-1508 ticket. It does not reinstate the superseded Fusion-route freeze, universal writer fencing, or a human approval before each authorized integration stage. Corporate remotes remain read-only.

## Reserve before an integration

From the intended target repository, capture the full `refs/heads/main` OID and inspect its identity and worktree state. Run `python3 <source>/tooling/scripts/ctn_main_ref_gate.py reserve <old-OID>`. Main must be a direct commit ref, not a symbolic ref to another branch (a symbolic `HEAD` pointing to direct main is normal). The command creates a unique retained `refs/heads/backup/pre-merge-*` at exactly that old commit, forces reference fsync, reads back its direct identity/OID and rechecks main. Failure means stop before preparing or advancing the candidate. Keep the returned backup reference; never reuse a stale reservation after another writer moves main.

Prepare and verify the candidate from that captured old commit. Advance main only with an explicit expected-old Git CAS. If using the matching reference-transaction hook, pass `CTN_MAIN_RESERVATION_REF` to that Git subprocess. The ordinary prepared-phase fallback preserves the old tip before the ref changes, not necessarily before candidate construction. The short-lived gate lock must not remain held across the main ref update.

## Restore a retained backup

Run `python3 <source>/tooling/scripts/ctn_main_ref_gate.py restore <fully-qualified-backup-ref> <expected-current-main-OID>`. Accepted namespaces are `refs/backup/` and `refs/heads/backup/`; the named ref must be direct and point at a commit, not a symbolic alias or revision expression. The command rejects unresolved index conflicts and symbolic main, retains a new durable backup of the expected current tip, and rechecks the selected target. It then starts an interactive Git `update-ref --stdin` transaction: no-deref update of named main with explicit expected-old CAS, no-deref verification of both retained refs, and `prepare`. While Git holds all three ref locks, it rechecks direct identities and exact OIDs before sending `commit`; a mismatch closes the explicitly started transaction so Git aborts at EOF. No-deref alone is insufficient because it could replace symbolic main with a direct ref; the prepared identity check prevents that silent replacement. The short-lived backup gate lock is released before this transaction, so the existing prepared hook can validate the command-scoped reservation without deadlocking. Ordinary Git writers cannot change these locked refs between the prepared checks and commit; this is not universal writer fencing.

On success the command prints JSON with the restored OID/tree, original backup, retained previous-tip backup, previous main, and before/after worktree status. Read those values back before continuing. CAS failure, symbolic identity, backup mismatch, hook refusal, protocol error or timeout means stop and keep every backup; never force/reset/clean to make recovery succeed. Git commands and transaction acknowledgements have bounded waits; stderr is drained into a temporary spool. Failure closes stdin and reaps the subprocess: an explicit `start` makes Git abort on EOF even when a prepare acknowledgement remains unread. A bounded kill fallback remains for a child that cannot terminate normally; forced termination can leave lockfiles, which must not be deleted blindly. A timeout or error after sending commit can leave the outcome uncertain: inspect refs and locks manually rather than infer that main stayed unchanged or retry blindly. Post-commit readback failure cannot undo a committed update. No backup is deleted on any failure.

Restoration changes refs only. Dirty tracked and untracked bytes remain untouched; when commit trees differ, Git status may change. The matching hook accepts the retained restoration target through command-scoped `CTN_MAIN_RESTORE_REF` and validates the current-tip reservation without creating a second backup. This source change does not install or alter a live hook.

## Upstream synchronization and evidence

Before an authorized sync, retain/read back the exact old main. After the read-only upstream fetch, retain a separate unique snapshot at the exact fetched upstream commit and verify both its OID and tree. That snapshot is not evidence that local main advanced. For every actual candidate integration, record source OID, fresh target old OID, unique backup/readback, resulting main and worktree state.

Parent verification exercised the actual restore CLI with a real installed hook in a disposable repository: previous/current backup and restored tree readbacks matched; dirty tracked and binary untracked bytes were preserved; stale expected-old restoration was refused. This is isolated command proof, not a claim that a product candidate was integrated or that every external writer is fenced. Backups are retained ordinary Git refs, not immutable storage. Same-user hook overrides and external ref writers remain outside this local procedure's guarantee.
