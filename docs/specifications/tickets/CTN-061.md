## Original Description

<!-- fusion-original-description:start -->
Resolve the pull request review feedback and address any failed CI checks.

PR: https://github.com/macro-inc/macro/pull/6825
Branch: gbirman/macro-3587-deleting-a-comment-from-a-minimized-margin-card-does-nothing → main

In a narrow document, anchored comments render as minimized badges that expand into a card, and the expanded card dismissed itself with a document `mousedown` listener that collapsed it whenever the press landed outside its DOM. The delete confirmation is a Kobalte dialog portaled to `<body>`, so pressing Delete collapsed the card first, unmounting the `MessageThread` that owns the dialog and the mutation before the click landed: no request was sent and the comment stayed. Wide margins never had the listener, which is why #6789 verified fine from the Discussion section.

**The card is now a Kobalte `Popover` anchored to the badge.** Kobalte's dismissable layers track nesting through the component tree, so the confirmation dialog, the emoji picker, and the action menus opened from inside the card are child layers even though they portal elsewhere, and pressing them is never an outside interaction. That fixes the whole class of bug rather than the delete dialog alone, and deletes the custom listener. The first version of this PR skipped the collapse when the press landed in `role="dialog" | "alertdialog" | "menu"`; that worked but was a heuristic a future overlay without one of those roles would silently break. Deferring the collapse (rAF or an await) was ruled out: a click needs mousedown and mouseup on the same element, and the gap is however long the person holds the button, so a deferred collapse would only race the press.

**Behaviour changes.** The popover content renders without a portal, as a sibling of the badge inside the margin, so it keeps the document's scroll, clipping and stacking exactly like the in-place card did, at the same `placeable + 1` z-index. The badge now stays rendered as the anchor instead of being replaced by the card, and the expanded card no longer feeds its height into the margin layout, so opening one overlays its neighbours rather than pushing them down. Escape now closes it. It opens without moving focus, matching the old card, and pressing the badge while it is open keeps it open instead of flickering shut. The card chrome moves out of `Thread` into a shared `ThreadCard`, and the `ref` and `width` props that only the minimized path used are removed from `Thread`.

Left out: the wide-margin `Thread` still renders in place with no dismissal of its own; it never had this bug, and moving it onto the same primitive is a larger layout change.
