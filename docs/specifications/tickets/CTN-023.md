# CTN-023 — Duplicate disposition: readable collapsed email signature preview

## Goals and boundary

- Define the minimum user-visible fix for the known signature case: convert the relevant rendered/Markdown content to readable plain text, retain link labels, and only then collapse whitespace and truncate to the preview limit.
- Keep expanded message rendering and stored/sent message content unchanged. Preview normalization is presentational only.
- Define adjacent cases so the signature fix does not damage ordinary inbound mail or silently broaden into all email rendering.
- Consolidate code, tests, review, and delivery in CTN-504; preserve CTN-023 and issue #5668 as source provenance.
- Keep [issue #5667](https://github.com/macro-inc/macro/issues/5667), noted by #5668 as a different collapsed-preview problem, out of this card unless the CTN-504 owner proves the defects share a root cause and explicitly revises that card's boundary.

## Behavior contract

1. For a Macro-authored sent message whose signature includes emphasis and Markdown links, the collapsed snippet must display readable text equivalent to `— from Cam Pak faith.tools • dotflowy.com`; it must not expose the signature's `*`, `[` or `]` syntax. The anchor text is retained; URLs need not be shown.
2. Derive plain text from the rendered message content where available (using the email's replyless content first when applicable so quoted history does not become the preview), with the sanitized HTML as a defined fallback. If only the Macro-authored Markdown source is available, remove supported inline emphasis/link syntax while retaining visible labels. Collapse whitespace and apply the existing preview limit after conversion; do not cut the visible output in the middle of an unconverted Markdown delimiter/label sequence.
3. For received messages with meaningful `body_text`, preserve that text as plain text except for existing whitespace normalization/truncation. Do not run speculative Markdown stripping on arbitrary received `body_text`: literal asterisks or arithmetic such as `2 * 3 * 4` must remain unchanged. Use sanitized HTML text only when the plaintext is missing/empty/whitespace, consistent with the existing fallback intent.
4. Other Macro-authored non-signature body content may use the same conversion path if it is actually stored/rendered in Markdown; tests must show the rule does not strip ordinary visible text or link labels. This is a safe adjacent format case, not a promise to rewrite all email bodies or resolve issue #5667.
5. Expanded rendering, outbound message body, reply/forward quoting, sender/date layout, and signature settings are unchanged. Do not alter signature insertion/sending behavior or sanitize trusted content differently as a side effect of preview generation.

## Acceptance

### Success

1. The concrete #5668 signature renders in the collapsed row without Markdown punctuation, with `Cam Pak`, `faith.tools`, and `dotflowy.com` readable and in the original visible order. Styling and clickable links are not required in the preview.
2. A truncation-boundary example proves conversion occurs before truncation: no dangling Markdown emphasis marker or partial `[label](...)` syntax is visible at the end. The plain-text result stays within the existing preview limit.
3. Macro-authored rendered/HTML content preserves readable paragraph/list spacing as a single-line snippet, collapses excess whitespace deterministically, and does not include quoted reply history when the replyless field exists.
4. Received mail with non-empty `body_text` retains literal asterisks (including `2 * 3 * 4`) and other user-entered plain characters; it does not get converted as if every inbound body were Markdown. If that text is empty or whitespace, sanitized HTML fallback produces readable text.
5. Expanded-message tests or focused UI inspection show the body/signature is unchanged. No persisted data, API schema, or send/signature-policy change is introduced.
6. CTN-504 owns the shared implementation and tests; CTN-023 is recorded as duplicate provenance only after its owner verifies that the receiving card includes this acceptance contract. No unreviewed code, CI, production, or merge status is described as green.

### Failure

- The collapsed sent signature still reveals Markdown syntax, link labels disappear, or truncation leaves malformed Markdown delimiters.
- The fix strips literal asterisks from received plaintext or alters visible non-signature text, includes quoted thread history despite an available replyless body, or changes the expanded message/outbound content.
- CTN-023 and CTN-504 independently implement the same snippet behavior, or #5668 is dropped without preserving its provenance and disposition.
- The PR's imported description, a historical check report, or this document is presented as evidence of current merge/deployment or passing tests.
- Work on the distinct #5667 symptom is silently pulled into scope.
