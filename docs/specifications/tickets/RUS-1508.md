## Goals

- Before every merge that updates a product repository's `main`, capture its current OID and create a new, uniquely named, retained backup ref to that exact commit. Read back the ref and verify the OID before merging.
- Before syncing local `main` to upstream, back up its exact old OID. After syncing, retain a distinct snapshot equal to the exact fetched `origin/main` OID and verify both its OID and tree.
- Read back refs and worktree state after each operation. Keep backup refs for rollback; restore only with an expected-old (compare-and-swap) ref update, and never delete a backup during rollback.
- Preserve dirty root-checkout files and all other user-owned work. Stop rather than reset, clean, overwrite, or silently discard it. These local checks do not prevent another writer from changing refs concurrently; detect unexpected movement and stop.

- No security, identity, privacy, credential, paid feature, certificate, or regulated-compliance work.

- No human approval before every stage: the user's current authorization covers this local integration work. Independent technical verification still applies at every step.

## Acceptance

### Success

1. Before each merge to product `main`, record its current OID, create a fresh uniquely named retained backup ref at that OID, read it back, and confirm exact equality. If creation or readback fails, do not merge.
2. Before upstream synchronization, back up and verify the exact old local-main OID. After fetching, retain/read back a separate post-sync snapshot ref whose OID and tree match the exact fetched `origin/main`. Do not infer that any local `main` ref moved from the existence of this snapshot.
3. After each operation, read back `main`, its applicable backup, and worktree state. If the result is wrong, restore only from the retained backup using an expected-old/CAS update, then verify the restored OID. Keep all backups.
4. Keep unrelated user data intact; report and stop on dirty/conflicted or unexpected state that makes the intended operation unsafe. Do not represent local backup checks as protection against concurrent external writers.
5. Report only observed outcomes. The existence of an integration commit does not mean local `main` has moved.

### Failure

Missing or stale starting OID, backup collision or readback mismatch, failed fetch/sync, unexpected ref movement, or an unsafe dirty/conflicted state means stop without advancing the target ref. If a CAS rollback fails because the ref moved, retain the backup and evidence and stop for manual recovery; never force the ref. Do not claim success from intended commands or configuration without readback.

## Work sequence

Run in the repository being synchronized or merged, after confirming its identity and intended `origin`. Inspect and preserve dirty user-owned files; their presence alone does not prohibit a ref update when the operation does not overwrite them. Stop if the proposed operation would overwrite or obstruct those changes. Commands below use new `refs/backup/` refs; choose a fresh unique suffix for every backup and keep the refs.

1. Inspect `git rev-parse --show-toplevel`, `git status --short`, `git show-ref`, and the current `main` OID. Record them without changing state. Identify dirty user-owned files and confirm the proposed operation will preserve them.
2. Before upstream sync, record `OLD=$(git rev-parse refs/heads/main)` and choose a new unique `PRE_BACKUP=refs/backup/main-pre-sync-<unique-id>`. Derive a zero OID matching the repository's hash length with `ZERO=$(printf '%s' "$OLD" | tr '0-9a-f' '0')`; create only if absent using `git update-ref "$PRE_BACKUP" "$OLD" "$ZERO"`. Read back with `git rev-parse "$PRE_BACKUP"` and require exact equality to `$OLD`. If creation or readback fails, stop.
3. Fetch the intended remote, then record `UPSTREAM=$(git rev-parse refs/remotes/origin/main)` and `UPSTREAM_TREE=$(git rev-parse "$UPSTREAM^{tree}")`. Apply the intended synchronization to local `main` only if it still equals `$OLD`; use the project's ordinary merge procedure, preserve dirty files, and stop on conflicts or unexpected changes. Read back and record the resulting local-main OID. After synchronization, choose a unique `POST_SNAPSHOT=refs/backup/origin-main-snapshot-<unique-id>` and create it with `git update-ref "$POST_SNAPSHOT" "$UPSTREAM" "$ZERO"` (the zero OID prevents replacing an existing ref). Read back its OID and tree; require exact equality to `$UPSTREAM` and `$UPSTREAM_TREE`. Preserve both refs.
4. The verified root `main` is now `0f002d8aa27cd4e022b71e7da55c58e51fcdaf52`, with parents `6efb9d2ade28dd5639265c1ac88e8dc46ea377f8` and old local-main commit `484c8708a901f74cf34fd74e99df2111f8ceba23`. The retained post-sync snapshot `backup/post-sync-origin-main-20260929-6efb9d2ade` points to exact fetched upstream `6efb9d2ade28dd5639265c1ac88e8dc46ea377f8` and its tree. Do not conflate the integration commit at `main` with the snapshot of `origin/main`.
5. For each candidate merge, identify source ref/OID and target repository. Immediately before that merge, recapture target `main` as `OLD` and choose a new unique backup name. Derive a same-length zero OID (`ZERO=$(printf '%s' "$OLD" | tr '0-9a-f' '0')`); create the backup only if absent with `git update-ref "$BACKUP" "$OLD" "$ZERO"`, then read it back and require exact equality. If target `main` moved since the merge was prepared, stop and reassess; do not reuse a stale backup.
6. Merge the intended candidate into the target using ordinary Git merge behavior. Do not push unless separately authorized. Read back `main`, the backup ref, and worktree status; record the result. On conflicts or any mismatch, stop without cleaning or resetting.
7. If rollback is necessary, first record the expected current `main` OID. Update the ref from that expected OID to the retained backup OID using an expected-old/CAS operation (for example `git update-ref refs/heads/main "$BACKUP_OID" "$EXPECTED_CURRENT"`). Read back `main` and verify it equals `$BACKUP_OID`; retain the backup and all evidence. If the expected-old update fails, stop rather than force.
