## Mission

The PR adds invalidation in `apps/web/src/lib/queries/storage/pr-mention-sync.ts`, but `crates/github/src/domain/service/sync.rs::process_webhook_event` calls `upsert_pull_request_foreign_entities` (which publishes `github_pull_request_updated`) before `handle_pr_open`/`handle_pr_edit`/`handle_comment_event` upsert the `github_pr_tasks` link. ## Acceptance and observable behavior

## Symptom Verification

- **Original symptom:** A task linked to a GitHub PR still shows no PR until page refresh.
- **Exact reproduction:** Mount task PR query with cached empty response; process a PR-open/edit or comment-link webhook with a new valid task ID; deliver the existing foreign-entity update before `github_pr_tasks` write. Immediate invalidation refetches `[]`; the write then completes with no subsequent signal. Reproduce this ordering in an automated test, not just a cache helper.
- **Assertion it is gone:** Rust domain tests show a link-update notification is emitted only after a successful new association is persisted, including comment path. Frontend mounted-query observer test starts with `[]`, delivers a saved-link event, refetches a populated list and asserts it changes without remount/reload. Early event/late write and no-write cases must be exercised at the actual service boundary; green builds alone do not count.
