## Goal and original user request

## What This Delivers

People can use the main screens, search and settings in Russian by default, including loading, empty and error messages, on desktop and mobile. They can choose English without losing their place or altering their own names, documents or messages. Missing translations are caught automatically rather than displayed as broken labels.

## Mission

Build typed ru/en catalogs, a Solid-reactive translation API and one locale policy for the web client: use Russian at first paint for the corporate profile; support an authenticated per-user English choice, readable runtime fallback and deterministic missing-key detection. Migrate authored UI chrome, shared controls and loading/empty/error states on principal routes, search and settings; document consistent Russian terminology. Keep routes, tabs, analytics, permissions, flags, search values and user-authored content unchanged. Backend messages and outgoing email belong to LOC-02 (RUS-1480); formats and inflections belong to LOC-03 (RUS-1481). Audit [S29,S30] confirms only static English copy, not existing centralized i18n or runtime acceptance.
