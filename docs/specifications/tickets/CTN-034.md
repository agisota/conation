## Goal and original user request

## What This Delivers

People can enter credentials supplied by their provider when adding a custom server, authorize it, and keep using it after access tokens expire. HubSpot is one example; other servers without automatic client registration can work without a vendor-specific release. Existing preset and automatically registered connections still work.

## Mission

Implement the reporter's preferred **option B**, not only a HubSpot-specific registry entry. Add optional per-user/per-server OAuth client credentials to the native custom Add server flow; encrypt them at rest **in both the server record and the temporary authorization state**, select them before registry/CIMD/DCR, preserve them through callback and reconnect/refresh, and keep existing paths intact. HubSpot's MCP URL is `https://mcp.hubspot.com` (root, not `/mcp`), and it derives scopes from its MCP Auth App. Repository drift from the historical report: the registry is `crates/mcp_client/src/domain/provider_registry.rs` and already ignores trailing slashes for Slack/GitHub; the current OAuth entry points are `OAuthService::start_authorization` and `resolve_client_config`.
