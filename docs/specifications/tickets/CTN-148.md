<!-- fusion-original-description:start -->
Resolve the pull request review feedback and address any failed CI checks.

PR: https://github.com/macro-inc/macro/pull/6738
Branch: wolf/improve-tool-calls → main

Tool-call rows in agent session transcripts said which tool the harness reached for, and hid a run of them behind a caret that gave nothing back.

### Rows lead with the act, not the tool

For a kind the fold already names, the row is a glyph plus a verb that morphs as the call settles — `⌨ Running… · cargo test` → `⌨ Ran · cargo test`. That morph is `ToolStatusTitle`, ported into this block a while back and until now wired only to the debug gallery.

### Tool names become words

For the tools only their name identifies — Macro's own, an MCP server's, a harness tool this block doesn't model — the name is split into words, its acronyms restored, and a leading verb given the same present/past pair (`component/parts/tool-name.ts`):

| raw | running | done |
| --- | --- | --- |
| `get_mcp_tools` | Reading MCP tools | Read MCP tools |
| `ReadContent` | Reading content | Read content |
| `SendChannelMessage` | Sending channel message | Sent channel message |
| `BashCodeExecution` | — | Bash code execution |

A name that doesn't start with a known verb keeps its words and doesn't morph — inventing a tense for `BashCodeExecution` would be guessing at what the tool did.

### The double expansion is gone

`ToolGroup` no longer folds a run into "Called 5 tools". Every call keeps its row — the row is already one line, so hiding it cost a click and paid back nothing, and it put two meanings on the same caret. Only a settled run of more than six folds, and only in the middle: first two, `⋯ 5 more tools`, last two. A live run never folds. Rows are keyed by part index rather than by part object, so a card you opened stays open while the run streams in or the fold opens.

### Failures read as failures

`muted` (`opacity-50`) becomes `failed`: the glyph and the error subtitle take the failure ink at full opacity. Fading the one row a reader is hunting for was backwards.

### Testing

- `bun vitest run src/features/block-agent` — 255 pass, including a new `tool-name.test.ts` and a rewritten `ToolGroup.test.tsx` (short run, folded middle, opening in place, live run never folds).
- `bun run type-check`, `just check` — clean.
- Not yet exercised in a browser; the new cards and both group shapes are staged in the debug gallery at `/app/component/agent-ui`.

### Deliberately not in this change

- Dropping the per-row `bg-surface` for a bare hover row (worth judging against a real transcript, not the gallery).
- `ToolErrorCard`, still ported-and-unused.
- `search` can't show its query — the fold's `search` detail carries only `paths` and `output`, so that's a Rust-side addition.
