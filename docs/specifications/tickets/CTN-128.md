Adds the complete backend for typed user databases, including schema operations, SQL reads/writes, relations, saved views, sharing, imports, snapshots, and the SDK.

PostgreSQL remains the source of truth. The service builds the caller's authorized catalog, materializes the referenced data into request-local SQLite, and executes SQL within resource limits. Writes become typed changesets that are validated and committed atomically to PostgreSQL under table-version guards; notifications publish committed versions.

- Database entities and database-owned property definitions use existing ownership/access infrastructure. Domain services own authorization and validation; HTTP adapters pass typed receipts and persistence adapters implement the transaction contracts.
- Column operations support safe conversions, first-entry inference, placement renaming/reordering/deletion, and linked records. Imports and starter provisioning have durable retry protection.
- The document storage service exposes metadata/schema operations, read-only `/databases/query`, writable `/databases/exec`, sharing, import, and snapshot endpoints. Generated contracts and SDK database/table/column handles accompany them.
- Existing frontend consumers handle the new entity enum safely. Database UI and agent-tool registration will follow in later PRs.

The [backend review guide](https://github.com/macro-inc/macro/blob/wolf/databases-core-backend/crates/databases/README.md) maps the SQL pipeline, permission boundaries, and persistence implementation. SQLx metadata is generated canonically and scoped to the 105 new query caches used by this backend.
