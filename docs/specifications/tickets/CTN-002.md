## Goal and original user request

## What This Delivers

Choosing a model in a chat makes it the starting choice the next time you create a chat, instead of requiring repeated selection. Existing chats keep their own choices; unavailable models fall back safely and other people's choices remain separate.

## Mission

Implement the reported existing-chat → new-chat model carry-forward at the actual model-picking and request-creation boundaries in both legacy AI chat and the newer agent-session flow. The proposed diagnosis is only a hypothesis: the legacy soup composer already saves its *own* selection, but an existing chat only saves its per-chat model; the agent new-conversation composer keeps an override in a signal and clears it after send. Use safe synchronous user-scoped browser persistence, preserve existing per-chat restore and plan limits, and keep a model chosen for one agent from leaking to another runtime. No backend schema or cross-device sync is required.
