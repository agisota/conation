## Goal and original user request

## What This Delivers

- People can use their own connected mailbox after a restart without entering credentials again; another account cannot use it.
- Revoking a connection stops new uses even when an earlier request finishes late.
- Operators can rotate protection keys without losing existing connections, while passwords and tokens stay out of account screens, agent responses, diagnostics and unprotected backups.

## Mission

Provide an owner/team/provider/purpose-scoped, server-only credential reference contract for future JMAP and CalDAV mailbox adapters and currently permitted Google/Microsoft OAuth and native MCP integrations. Persist AEAD/envelope ciphertext and non-secret version metadata in MacroDB, keep wrapping keys in a separately managed source integrated with RUS-1456, and resolve plaintext only for an authorized bounded server operation. Migrate legacy FusionAuth identity links and native MCP grants with resumable conversion and generation-fenced revocation, preserving login, multi-mailbox and agent behavior. `crates/email/src/domain/models/link.rs::Link` is mailbox metadata, not the FusionAuth identity-provider link that carries `token`. RUS-1454 owns technical/runtime secret delivery; RUS-1487 owns PIPEDREAM_* enablement and provider-specific OAuth KMS contracts. Do not build mail/calendar sync.
