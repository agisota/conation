# CTN-020 — Duplicate disposition: local MCP workspace support

## Situation

CTN-020 is imported from [Macro issue #5673](https://github.com/macro-inc/macro/issues/5673). Its user asks whether `mcp_service` and `mcp_auth_proxy` can serve a locally hosted workspace under `just run_local`/`stack`, and how an external MCP client could reach it. The report's checks (no Compose/`just` entry, Caddy fallback at a guessed proxy URL, and SQLx connection refusal when starting the binary without `run_local` environment injection) describe the reporter's earlier checkout/environment; they are not current-state proof.

The source task records `nearDuplicateOf: CTN-027`, score `1`, and `pausedReason: duplicate-decision-required`. CTN-027 has the same title and substantially identical issue description. Treat CTN-020 as a duplicate tracking record, not a second implementation. Keep its ID and issue provenance visible; route the one product question to CTN-027. This document neither changes Fusion task metadata nor records an operator's final duplicate decision.

Read-only inspection of the documentation checkout (`/Users/t/Projects/CTN-apply-rus-ctn-20260925b`, `git rev-parse --show-toplevel` confirmed that root) shows that local support has moved since the issue's reported checks:

- `tooling/xtask/crates/xtask_local/src/local/inventory.rs` registers `mcp_service` as a non-optional `Mode::Local` Rust service. It has no host port and no proxy route; its documented local consumer is the agent egress proxy, which dials `mcp-service` over the Compose network.
- `docker/docker-compose.yml` defines `mcp_service` with `/app/out/mcp_service`, `MCP_PUBLIC_URL=http://mcp-service:8080`, Redis, and PostgreSQL/FusionAuth dependencies. It does not publish a host port. There is no standalone `mcp_auth_proxy` Compose service; the `mcp_service` binary imports its router/auth behavior from the `mcp_auth_proxy` crate (`services/mcp_service/src/main.rs`, `context.rs`).
- `services/mcp_service/src/main.rs` starts a Streamable HTTP MCP endpoint at `/mcp`; it applies OAuth 2.1/FusionAuth authentication. The service's own comments and local inventory distinguish this in-network agent-proxy path from an interactive external MCP client path.
- `tooling/just/xtask.just` delegates `just run_local` and `just status_local` to xtask. Compose presence alone does not prove that the generated local stack starts successfully or that a client can complete MCP initialization and invoke a tool.

These are checked-in configuration/code facts, not a live run of `run_local`, not a runtime reachability test, and not proof that arbitrary host/external MCP clients can access a local workspace. Current local code supports a bundled internal consumer; standalone/external access remains unproven and is not implied by the hosted MCP deployment.
