# CTN-016 — Preserve trailing Unicode modifiers during cleanup

## Situation

CTN-016 is imported from [Macro issue #5705](https://github.com/macro-inc/macro/issues/5705). Its requested behavior concerns the **trailing cleanup of stored email subjects and snippets**, not Unicode normalization or composer subject generation. In `services/email_service/src/util/process_pre_insert/clean_message/clean_subject_snippet.rs`, `remove_trailing_special_chars` first trims trailing whitespace, then cuts at the last character not classified as invisible. The current predicate includes broad combining-mark ranges and U+FE00–U+FE0F variation selectors. As a result, trailing user-authored modifiers can be discarded.

The task is paused with `pausedReason=duplicate-decision-required`; its source metadata identifies CTN-503 as a 1.0 near-duplicate, not as a completed resolution. CTN-503 is tracking PR [#6373](https://github.com/macro-inc/macro/pull/6373) and the same issue. Its source task says U+034F COMBINING GRAPHEME JOINER remains cleanup noise while combining accents and variation selectors are preserved. This is evidence of a likely single implementation, not proof that the PR is currently merged, accepted, or correct. Keep CTN-016 visible until an authorized duplicate decision records its disposition.

## Goal and user scenario

When a person receives an email with a subject or snippet ending in a decomposed accent or emoji presentation selector, cleanup must not change the meaning or presentation of that text. It must continue removing the trailing whitespace and formatting noise this helper already targets.

**Before:** `Cafe` followed by U+0301 COMBINING ACUTE ACCENT can be cut back to `Cafe`; an emoji ending in U+FE0F can lose that selector.

**After:** those input suffixes are preserved as Unicode code points by cleanup. A trailing targeted formatting control is still removed: `Cafe` + U+0301 + U+200B becomes `Cafe` + U+0301. No NFC/NFD conversion is performed.

## Scope and boundaries

- Preserve trailing combining marks from all Unicode ranges currently misclassified by the helper (U+0300–U+036F, U+1AB0–U+1AFF, U+1DC0–U+1DFF, and U+20D0–U+20FF), along with variation selectors U+FE00–U+FE0F; retain order and code points.
- Keep trimming trailing whitespace and already-targeted formatting controls (including zero-width space/non-joiner/joiner, BOM, NBSP, word joiner, the existing general-punctuation format ranges, and the specifically retained U+034F cleanup behavior recorded by CTN-503).
- The function is used by `clean_message_subject_snippet` for message subjects and snippets, and by thread subject/snippet cleanup. Verify the production entry points as well as the helper.
- Do not normalize, transliterate, rewrite, or otherwise change Unicode. Do not change leading or internal whitespace. An internal combining mark is not itself a trailing-cleanup target.
- This is independent of CTN-017: that card classifies a **forwarded subject prefix** while parsing quoted body content. It must not broaden this cleanup predicate or change body-reply extraction.
- This is independent of CTN-018: CTN-018 handles absent/empty source subjects when generating `Re:` / `Fwd:` composer subjects. It does not own preservation of trailing code points during pre-insert cleanup, and CTN-016 must not duplicate its composer change.

## Acceptance

### Success

1. `remove_trailing_special_chars` preserves `Cafe` followed by U+0301 COMBINING ACUTE ACCENT; the visually composed `café` example is not reduced to `Cafe`.
2. Representative trailing combining marks from U+0300–U+036F, U+1AB0–U+1AFF, U+1DC0–U+1DFF, and U+20D0–U+20FF, and variation selectors from U+FE00–U+FE0F, remain in exact output.
3. Targeted trailing whitespace/format controls are still removed, including when they follow a meaningful accent or selector; removing the noise must not remove the preceding modifier.
4. Subjects and snippets cleaned through their production entry points retain these meaningful trailing code points. Middle-of-string content and leading/internal whitespace are unchanged.
5. Tests demonstrate the boundary by checking exact output/code points, not only visual rendering.

### Failure cases / negative cases

- Any accent or variation selector is dropped, reordered, or normalized.
- Fixing the example by exempting only U+0301 or only one emoji, while leaving the specified modifier classes vulnerable.
- A trailing target control or whitespace is no longer cleaned, including the established U+034F behavior documented in CTN-503.
- Leading/internal text is modified, or this work changes composer prefixes, missing-subject behavior, or replyless-body parsing.
- A second implementation is added while CTN-503 / PR #6373 is the chosen owner for the same behavior.
