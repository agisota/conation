> [!NOTE]
> **Medium Risk**
> One-time production data migrations on core ownership metadata; mitigated by idempotent inserts and source-row filters, but still affects every historical resource row on deploy.
>
> **Overview**
> Adds **five idempotent SQLx migrations** that populate the `entity` table from legacy resource tables (`Document`, `Project`, `Chat`, `agent_session`, `scheduled_action`) so ownership registry covers rows created before dual-write.
>
> Each migration uses `INSERT … SELECT … ON CONFLICT (id) DO NOTHING`, maps owners to `user` + lowercased `macro|%` ids, and for Prisma-backed tables filters to valid UUID ids and applies timezone normalization on timestamps. Agent sessions and scheduled actions copy existing timestamptz columns directly.
>
> **Docs** (`CLAUDE.md`, `DATABASE_DEVELOPMENT.md`) now steer contributors toward migration-based backfills when a single SQL pass is enough, document constraint-safe filtering (e.g. UUID regex before cast), warn against down migrations that would delete live dual-written rows, and point to the batched `[[bin]]` pattern when table locks are a concern.
