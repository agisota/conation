## Goal and original user request

## What This Delivers

An operator can run a durable private mail server under their own domain and tell whether it is healthy. Verified invited colleagues each receive exactly one mailbox even when sign-up repeats; mail between colleagues remains readable after restart without Gmail. Service mailboxes and backup coverage are explicit, while Internet delivery and the app's synchronized inbox remain future work.

## Mission

Extend the *delivered* RUS-1448 production self-host installation with pinned, opt-in Stalwart, persistent account/message/config state, protected administration and a TLS/JMAP endpoint on RUS-1451's internal route. Implement RUS-1459's server-only pending-profile handoff: a verified invited user can have one same-owner/tenant principal confirmed *before* RUS-1459 activates corporate membership. Use RUS-1457 protected credential references and register mail with RUS-1449's backup contract. Prove local A→B delivery and direct JMAP read after restart, without substituting Gmail, CTN inbox sync or public Internet deliverability.

- [ ] **Exact reproduction** — On a disposable *production* profile with Gmail credentials/routes disabled for the test, enroll verified invited A and B via RUS-1459's real registration entry; send uniquely identified A→B mail through Stalwart internal submission; read B's exact message via B-scoped server JMAP Email/get. - [ ] **Assertion it is gone** — Committed automated production-profile + registration integration test asserts one server account per A/B, exact message available in B's JMAP before/after restart and inaccessible to A/stranger, idempotent retries, denied claims without secret leak/ownership change, and JMAP/disk failures return non-ready/failure. Mock-only, Gmail, CTN inbox polling, queued event or green build alone cannot satisfy this.
