## Goal and original user request

## What This Delivers

People can add a server by its own address even when it is not in the connector catalog. Their custom server and catalog connections can coexist, and the tools of an enabled, reachable server are available to the agents that advertise them. People can see and manage both kinds of connection without losing existing connections.

## Mission

Restore the native URL-based MCP connector in the existing Connections experience without removing Pipedream or reversing the newer sidebar. The native stack already has user-scoped `/mcp/servers` CRUD, OAuth callback and encrypted credentials; the frontend conditionally hides it in `McpConnections`, while `mcp_select` currently chooses *only* Pipedream when any Pipedream row exists. Make both usable in AI chat, and carry the same authorized owner connections into agent-harness sessions through the established egress boundary; preserve Pipedream behavior and avoid copying secrets into agent settings or sandboxes. Issue #6649 is the acceptance contract; PR #6151 is historical design context, **not** a patch to merge wholesale (it combined an unrelated Connections/sidebar restructure).

## Acceptance and observable behavior
