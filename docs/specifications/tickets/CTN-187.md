A previous slop PR had put the inline detail content ownership in the Block Orchestrator. This corrects that and moves it to a more sensical location. ---

> [!NOTE]
> **High Risk**
> Refactors core split navigation, history, mobile swipe, and duplicate-entity policy across many entry points; incorrect reuse/toast/focus behavior would affect daily navigation.
>
> **Overview**
> Moves **entity “already open” tracking** from the block orchestrator into the split layout via a local `contentInstanceRegistry`, with `findOpenView` / `registerOpenViews` so splits, popovers, and inline details all participate in deduplication.
>
> **`openWithSplit`** now returns explicit **`opened` | `reused` | `unavailable`** outcomes (plus `sourceOwner` / `owner`) instead of only a handle. Call sites that open from lists, Cmd+K, sidebar, agents, etc. show **Content already open** only when reuse comes from a *different* owner; silent reuse + `activate` covers mentions, notifications, and inline previews. Blocked replaces route focus to the owning view via `openWithSplit` without layout-manager toasts.
>
> **Navigation stacks** pass a **`restore` vs `navigate`** reason so restored selections do not steal focus or toast. **Split history** gains a reactive **`canVisit`** rule (per-split ownership) so back/forward and `backTo` skip entities open elsewhere without focusing them; mobile swipe layout is updated to promote/reuse panes and rebuild background history safely.
>
> **UX:** sole visible non-list splits get **Return to list** close behavior via `closeSplitOrReturnToList`. Docs updated for the new toast/focus rules. Large test coverage for preview guard, layout manager, notifications, and BlockLink.
