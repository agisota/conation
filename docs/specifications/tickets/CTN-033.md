## Goal and original user request

## What This Delivers

People can schedule an agent they already host, see it among their automations, run it on demand, and read its replies and run history in Macro. Macro securely calls the agent without exposing its verification secret in routine lists or edits. Existing Macro-powered automations keep working.

## Mission

Extend `scheduled_action` with `ActionKind::RemoteAgent` and a typed `RemoteAgentTask { endpoint_url, user_prompt, agent_label }`, preserving `Agent`. Choose reporter-preferred option (a) as this plan's implementation decision, not a claim of maintainer approval: server-generated per-action signing secret in an additive nullable `scheduled_action.signing_secret`, one-time owner-visible provisioning/rotation, and `webhook_signature`-compatible signed outbound POSTs. Choose one attempt per run; public HTTPS by default with an explicitly configured HTTPS-only private-target exception. Keep policy and attempt decisions in domain, HTTP/DB in outbound adapters, caller authorization in domain service, composition in `bins/service.rs`. "Agents view" here means the existing Automations list; this is NOT a new conversational-agent principal, bot token, webhook reuse, or Hermes-specific integration. Issue line numbers describe an earlier revision: current executor is `outbound/inprocess_executor.rs` and `docs/testing.md` does not exist in this checkout; use the supplied checklist below.
