## Goal and original user request

## What This Delivers

People consulting the MCP reference will see only capabilities actually offered by Macro's MCP server, along with a clear explanation of why email sending, integration-tool discovery, rich result displays, and the older thread-reading name are not available there. ## Mission

Take the **documented-with-exclusions** branch of the reporter's explicit acceptance criterion, rather than registering unsafe or nonfunctional tools to make counts agree. `services/mcp_service/src/main.rs` builds `ai_tools::tools_for(AiHost::Mcp)` per MCP service instance; `AuthenticatedToolService::list_tools` lists that collection without pagination, and `call_tool` dispatches to it. In contrast, `apps/docs/scripts/generate-mcp-tool-pages.ts` uses `gen_tool_schemas`, whose `all_tool_frontend_schemas()` merges the chat host and a phantom `ReadThread` exclusively for frontend type generation. Give docs their own schema export from the existing MCP host toolset, keep the chat typegen output unchanged, regenerate the MCP pages/navigation, and explicitly explain the host differences. Do not conflate an in-app agent's connected integrations or composer with an external MCP client's capabilities.
