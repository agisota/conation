Shows channel renames, participant changes, picture updates, and completed-call durations inline with messages.

The existing messages API merges persisted activity and messages server-side into tagged `entries` with shared cursor pagination. Activity reads remain behind a domain port so other message timelines, including discussions, can adopt the same model later. Adds picture-change activity, refresh notifications after persistence, and updated web/SDK timeline contracts. The UI renders compact, fixed-height system rows while preserving scroll anchors.

Validated with affected Rust, web, and SDK tests, TypeScript and repository checks, and recorded Chrome QA covering live updates, pagination, reloads, and narrow layouts.

> [!NOTE]
> **Medium Risk**
> Large changes to message timeline pagination, cache reconciliation, and scroll behavior; bugs could cause wrong ordering, lost optimistic state, or scroll jumps, though scope is channel UX rather than auth or billing.
>
> **Overview**
> **Channels now interleave persisted system activity with messages** in one paginated timeline (`entries` with `message` / `activity` tags), backed by new `activity_events` SQL and wiring of the `activity` crate into messages and related workspace targets.
>
> The **web channel UI** renders compact system rows (rename, members, picture, call ended) via `SystemActivity` / `ThreadRow`, breaks sender grouping across activity, and feeds the virtual list per-row size estimates. **TanStack Virtual** is patched so follow-on-append works when delayed activity inserts or server acks change the last key without growing count, with optional iOS scroll deferral and an initial scroll offset readback for short lists.
>
> **Timeline fetching and cache logic** is reworked: channel loads use `include_activity`, authoritative refresh/reconcile (`timeline-refresh`, `timeline-entries`) preserves optimistic posts/edits/deletes and pending mutations across multi-page refetches, and **activity commits** trigger timeline invalidation (including while the first page is still loading). Document/discussion paths stay message-only. Channel picture updates only run when the ID actually changes, and picture upload polling waits longer for queue retries.
