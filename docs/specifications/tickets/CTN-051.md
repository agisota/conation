## Goal and original user request

## What This Delivers

Users can save their own model server address, optional key and model name, then select that model in a conversation. Self-hosted users can connect reachable local servers, and users can connect permitted cloud providers. Keys remain private and built-in model choices remain available.

## Original Description

<!-- fusion-original-description:start -->
It would be useful to support configurable OpenAI-compatible model endpoints, including local servers such as Ollama, LM Studio, vLLM, and llama.cpp, as well as third-party cloud providers.

A configurable base URL, API key, and model name would allow users to choose their own provider for privacy, offline use, lower cost, or development purposes.

Source: https://github.com/macro-inc/macro/issues/4795

## Mission

Implement one user-owned OpenAI-compatible Chat Completions configuration with base URL, optional API key and exact model name, addressed by a stable non-secret selection ID from classic chat and the in-memory Macro agent. Reuse the compatible branch of `ModelRouter`, Cursor's owner-scoped encrypted credential-store pattern and current model discovery/selection. A local endpoint must be reachable from the backend (hosted Macro cannot access a user's laptop via `localhost`): explicitly document self-hosted/container networking and restrict hosted configurations to safe publicly reachable HTTPS targets. Self-hosted local servers commonly use non-default ports; allow valid explicit ports for backend-reachable local URLs under the self-hosted policy rather than rejecting them globally. Preserve Anthropic-native, OpenAI Responses and other agent runtimes. Supporting provider-specific protocols, automatic model discovery, all background AI tasks and guaranteeing tool support from every compatible server are non-goals.
