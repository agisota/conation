<!-- fusion-original-description:start -->
Resolve the pull request review feedback and address any failed CI checks.

PR: https://github.com/macro-inc/macro/pull/6682
Branch: fix/command-search-cache-refresh → main

With GraphQL caching enabled, Command Menu can omit a channel that the server has already returned. The channel list was replaced with the partial normalized-cache list; background backfill intentionally hydrates silently, so an open search could remain empty even after indexing completed.

Keep the complete server channel inventory available to search and overlay cached metadata by ID. Cached updates and new cached channels still participate, while server-known channels remain searchable before backfill catches up. No cache invalidation or hydration protocol changes are needed.

Reproduced on main 303d1c0: after a cold cache reset, searching `bug-repo` omitted the known channel even after all three backfill pages succeeded. After the fix, it appears within the first recorded search interval, stays visible, and opens the expected channel.

Validation: all three new regression tests fail before the fix and pass afterward; full web TypeScript check, `just check`, whitespace checks, and recorded cold-cache Chrome validation pass. Before/after clips are supplied in the local review bundle at the user's request. No media files are committed.
