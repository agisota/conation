## Mission

Diagnose and fix issue #6015's Ubuntu VM `just run_local` passwordless-login failure over browser port forwarding. Current HEAD already supports same-origin local routing in `tooling/xtask/crates/xtask_local/src/local/frontend.rs`, `apps/web/src/lib/core/constant/servers.ts` and `apps/web/scripts/local-dev-server.ts`; the reported bundle's `ws://localhost:8090` is evidence to compare with the served build, not proof that HEAD still has the same fault. Reproduce the precise failing boundary before selecting the smallest compatible repair; do not replace the local-stack architecture.

## Acceptance and observable behavior

## Symptom Verification

- **Original symptom** — VM port-forwarded login gives `Invalid code.`, submitted-code 401, refresh 400 (`no access token to refresh`), protected endpoint/email-link 401, failed `ws://localhost:8090/connection-gateway`, and sometimes navigation `AbortError`.
- **Exact reproduction** — run `just doctor-local` and `just run_local` with identical instance/port base on a VM; forward ONLY the printed frontend port via `ssh -N -L <browser-port>:127.0.0.1:<vm-frontend-port> <vm-host>`; open `http://localhost:<browser-port>/app/login` in a fresh browser profile. Request code for a new test email, use current returned local code or latest Mailpit message, submit once; record request origins/status, Set-Cookie, redirect and WS upgrade. Contrast HTTPS reverse proxy if used. Do not reset DB/volumes, share credentials or expose the stack publicly.
- **Assertion it is gone** — run a real automated browser/integration regression which reproduces a forwarded-origin code request and verification through production paths, then asserts an authenticated protected request and successful same-origin WS upgrade; ensure invalid/reused codes remain rejected. Pair deterministic auth-fixture browser coverage with real proxy HTTP/WS integration if a live FusionAuth stack is unavailable. A green build alone is insufficient; anonymous 401 is not failure unless it persists after valid login.
