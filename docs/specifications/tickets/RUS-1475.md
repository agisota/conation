## Mission

After RUS-1451 delivers its own-domain runtime route and trusted installation identity, add one installation-scoped read snapshot in MacroDB, an anonymous auth-service `GET /branding/bootstrap`, and a non-suspending Solid `BrandProvider` mounted above public and signed-in routes. The complete public contract is `name: string`, `logo: string | null`, `favicon: string | null`, `links: { website: string | null, support: string | null, privacy: string | null, terms: string | null }`, and monotonic `version: number`; no extra internal fields or secrets. The name and links remain present when logo/favicon are null. The server selects the installation from trusted DEP-05 configuration or a verified proxy identity (never user input or raw Host); an absent row yields safe five-field defaults with version 0, but an absent/untrusted installation identity fails closed. Preserve one read API for RUS-1477 to extend with ACL-protected production writes and versioned owned assets; do not implement that write, RUS-1476 editor, or RUS-1478 screen substitutions. Never use personal ThemeV3 or localStorage as the branding source.
