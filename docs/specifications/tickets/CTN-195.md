<!-- fusion-original-description:start -->
Resolve the pull request review feedback and address any failed CI checks.

PR: https://github.com/macro-inc/macro/pull/6690
Branch: synoet/activity-human-sync → main

Human document body edits were missing from Activity. Sync now collects the actual authenticated editors and sends their identities with its existing snapshot/search notification. DSS records one Edited activity when an editor starts editing, then suppresses further events until that editor has been inactive for five minutes.

The Durable Object only deduplicates and drains an in-memory editor list: no Activity storage, per-edit background tasks, extra timers, or additional normal-path network calls. Human HTTP edits do not add oplog attribution writes. Agent attribution is preserved; anonymous edits, duplicate updates, viewers, and idle peers add no editors.

One content event still triggers one search extraction. DSS's separate Activity consumer owns the shared Redis inactivity window, with atomic expiry refresh, a bounded timeout, and best-effort failure handling. Search and document persistence never wait for Activity. An uncertain Redis timeout may lose the Activity row for that continuous editing session; this is an intentional best-effort limit. Old payloads remain supported, and an older DSS rejecting the new field gets one retry without Activity hints.

Validation:
- 251 documents, 50 Activity, and 28 Sync Rust tests passed; strict Clippy, rustfmt, Biome, ast-grep, and explicit oxlint checks passed. `just check` passed before schema generation; its all-generated TypeScript inputs were linted explicitly with the same rules because the wrapper treats ignored files as an error.
- 91 compiled-Worker tests cover editor batches, duplicate/read-only filtering, stalled and failing DSS, and legacy request fallback.
- All five local review categories passed. Redis tests cover concurrent starts, sliding expiry, independent identities, and replay decisions.
- 84,000 local benchmark ACKs, zero failures; no observed latency regression, including a sustained run through periodic snapshot saves. Local Miniflare measurement, not a production latency guarantee.
- Uncut Chrome proof: first edit 52 → 53 actions; continued editing and five real idle minutes remain 53; resumed editing 53 → 54. Videos and benchmark artifacts stay outside the PR.

Reconciled with main. No database migrations or generated proof artifacts are included.

> **Medium Risk**
> Changes Activity feed semantics and adds a Redis-backed debounce on the document activity consumer path; failures are best-effort but could hide or delay edit events during mixed-version deploys.
>
> **Overview**
> Fixes missing **human document edit** activity by extending sync content notifications with batched **`editors`** (while keeping legacy single **`actor`** / **`on_behalf_of`**), then turning those into **Edited** rows in the Activity consumer.
>
> **Sync** accumulates distinct verified editors (human **`user_id`**, agent **`actor`**, no anonymous/view-only/replay noise) in the Durable Object and sends them with the existing snapshot/search DSS call—no extra per-edit HTTP. **DSS** accepts **`editors`** on `sync-content-updated`, publishes them on `document.sync_content_updated`, and wires the Activity Kafka path through an **async** dispatcher plus **Redis** session debounce (~5 minutes idle per actor/subject/document). Invalid editor hints are dropped so search/activity classification cannot wedge on bad IDs.
>
> Opening without edits still emits no edit activity; Redis/timeouts/errors **suppress** Activity hints best-effort without blocking saves or search extraction. Older DSS builds get a **422 → empty-body retry** so extraction keeps working without editor metadata.
