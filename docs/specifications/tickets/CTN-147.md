<!-- fusion-original-description:start -->
Resolve the pull request review feedback and address any failed CI checks.

PR: https://github.com/macro-inc/macro/pull/6739
Branch: gab/messages/channel-mentions → main

Puts the Discussion's channel mentions section back, behind `enable-document-channel-mentions` and off everywhere until PostHog says otherwise. The previous PR removed it rather than restyling something that was about to be gated, so this rebuilds it instead of reverting.

**The endpoint comes back with it.** `GET /messages/{parent_type}/{parent_id}/references` was deleted from `main` in #6757 because, once the old UI was gone, nothing called it — and a dead endpoint carrying an access-control decision is the kind that rots quietly. This branch restores that slice verbatim (route, `MessageService::referenced_threads`, the `comms_entity_mentions` query, the `ReferencedThread*` types, `MessageReferenceAccess::can_write`, and the regenerated OpenAPI/SDK/web artifacts), so the endpoint returns in the same change as the feature that calls it. The split was deliberate: `main` never carries the half nothing uses, and if this feature is dropped, nothing needs reverting. Since it is a straight revert of a straight deletion, the generated artifacts were confirmed by re-running codegen and diffing to zero rather than trusted.

**The attribution now uses the format the app already had.** The old section rendered `From {channel_name}` as an underlined link, and `channel_name` is null for a DM or an unnamed private channel — so it read "From Channel conversation". The References side panel has always solved this: it renders the channel as an `InlineItemPreview`, which resolves the channel's current name and falls back to participants. This uses the same chip, so that case now reads "From Dana Example, Eve Example". Clicking it goes through `navigateToChannelMessage` like References does, rather than a bare `<a href>`.

**The checkbox is gone.** Gating is the flag's job now, so the always-visible `<input type="checkbox">` is replaced by a "Channel mentions" heading with a count that only renders when there is at least one — which also retires the "No channel threads mention this document." empty state. The trade is that the discovery query is no longer user-gated: with the flag on it fetches when the Discussion opens and polls every 30s, where before it waited for the checkbox. That cost is bounded by the flag and by the section only mattering to people who have it.

**The disclosure caret** was the literal characters `▾`/`▸`, which render as a solid block in this font — the section header looked like it had a bullet. It now uses the phosphor caret the side panel uses.

The flag now exists in PostHog (project MACRO, `enable-document-channel-mentions`), created disabled with a team-only release condition, so merging changes nothing for anyone until it is turned on. `VITE_ENABLE_DOCUMENT_CHANNEL_MENTIONS=true` still overrides it locally and on a preview build.

With the flag off the section does not render and `useChannelReferenceThreadsQuery` is disabled, so it neither fetches on open nor polls. The threads stay channel-owned in every other respect: replies, edits and reactions post to the channel, `Copy link` yields the channel link, and a thread from a channel the viewer cannot post in has no reply, edit or delete controls.
