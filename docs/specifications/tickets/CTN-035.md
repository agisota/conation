## Goal and original user request

## What This Delivers

Replying to an email goes to the address its sender designated for replies, rather than an automated sending address. When no reply address is provided, replies still go to the sender as before. The recipient shown before sending matches the address that will receive the email.

## Mission

Make the received message's RFC 5322 Reply-To mailbox(es) available to the shared email composer through both thread transports, then use them in the existing recipient derivation for Reply and Reply All without changing threading or overriding persisted/user-edited draft envelopes. Gmail ingestion already stores all provider headers in `headers_json`; the REST `ApiMessage` includes that data, whereas the GraphQL `EmailThreadMessageFields` fragment and feature projection omit it. Expose only parsed Reply-To contacts across the boundary, reuse the existing address parser's behavior rather than treating a quoted display name as an address, and keep the compose/sending pipeline unchanged after recipient selection.
