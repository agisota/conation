# Медиа в стартовых документах Conation

Этот инвентарь охватывает все шесть шаблонов, которые встраиваются в
`document_storage_service`:

- `learn_about_tasks.md`;
- `advanced_task_features.md`;
- `how_we_use_tasks.md`;
- `macro_how_to_guide.md` (историческое имя файла, не пользовательский бренд);
- `markdown_template.md`;
- `canvas_template.canvas`.

## Текущее состояние

После русификации шаблоны не ссылаются на изображения, GIF или видео.
`canvas_template.canvas` содержит только векторные узлы, линии и текст; внешних
растровых ресурсов в нём нет. В `markdown_template.md` также больше нет
`document-mention` с типом `image`.

Legacy-обработчик `/documents/initialize_user_documents` отдельно перечисляет
объекты из S3-префикса `ONBOARDING_DOCUMENTS/`. Это динамический источник, а не
ссылка из шаблона: набор объектов, их имена и метаданные отсутствуют в
репозитории. Поэтому он не выдаётся здесь за проверенный локальный asset.

## GIF

GIF-файлов среди текущих или удалённых ссылок нет, поэтому покадровая разбивка,
длительность сцен и длительность анимации неприменимы.

Происхождение и лицензия двух удалённых PNG в репозитории не зафиксированы.
Инвентарь описывает проверенные сетевые ответы и содержимое файлов, но не
приписывает им неподтверждённое авторство.

## Машинный индекс и полный визуальный реестр assets

Файл [`assets/ASSET_MACHINE_INDEX.tsv`](assets/ASSET_MACHINE_INDEX.tsv)
содержит текущие 312 строк машинного индекса для PNG, JPEG, GIF, WebP, SVG, ICO,
BMP и AVIF. Для каждой записи записаны формат, число байтов, размеры, SHA-256,
число кадров и длительность там, где формат позволяет получить их без
декодирования изображения. Индекс воспроизводится командой:

```bash
python3 docs/assets/generate_asset_index.py
```

Колонка `human_visual_review` в машинном индексе намеренно равна `required`:
этот файл фиксирует метаданные, а результаты отдельной визуальной проверки не
подменяют машинный статус. Граница канонического product-набора зафиксирована в
[`assets/BATCH4_RU.md`](assets/BATCH4_RU.md): из 312 строк исключены 15
не-product записей — три поздние копии в `apps/docs/brand/` и 12 PNG fixtures
email-rendering. Поэтому полный набор содержит 297 canonical production-ассетов.

Все 297 canonical production-ассетов открыты и описаны вручную ровно один раз в
четырёх связанных частях реестра:

- [batch 1 — 73 ассета](assets/ASSET_VISUAL_INVENTORY_RU.md), включая все 66
  кадров единственного GIF;
- [batch 2 — 73 ассета](assets/BATCH2_RU.md);
- [batch 3 — 75 ассетов](assets/BATCH3_RU.md);
- [batch 4 — 76 ассетов](assets/BATCH4_RU.md).

Пользовательские Conation masters и platform-derivatives также перечислены с
точными SHA в [`../apps/web/public/brand/README.md`](../apps/web/public/brand/README.md).

Tauri-файл `apps/web/tauri/src-tauri/icons/icon.icns` не входит в этот
312-строчный набор расширений. Он и остальные platform-копии были штатно
перегенерированы Tauri CLI из квадратного Conation master; их provenance,
размеры и representative SHA приведены в brand README.

## Политика идентификаторов стартовых документов

Текущая greenfield-ветка строит UUIDv5 из канонического пользовательского ID с
префиксом `conation|` и неизменяемой seed-строки. Поэтому повторный вызов для
одного пользователя идемпотентен, но UUID намеренно отличается от UUID старой
установки с пользовательским префиксом `macro|`.

Исторические seed-строки `Macro how to guide` и `How we use tasks at Macro`
остаются внутренними входами хеша и не показываются пользователю. Менять их без
миграции нельзя. В upstream-sync ветке потребуется отдельная версионированная
политика совместимости или миграция существующих starter docs; простое
переключение префикса создаст второй набор документов.
