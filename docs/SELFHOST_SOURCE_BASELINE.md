## What the collector proves and does not prove

`tooling/scripts/source-baseline.mjs` is a Node CLI; it performs no network requests, executes only read-only Git queries, does not run/build services, and writes only an explicitly named new manifest outside the checkout (or stdout by default). Supply all six paths: `--checkout`, `--expected`, `--cache-wasm`, `--agent-wasm`, `--dist`, `--binaries`. Output roots may be outside the checkout. `--expected` is an operator-authored JSON input with the **full** checkout `sourceSha` and a separate service/package/bin/path mapping derived from `nix/cloud-storage.nix`. Binary paths are relative to `--binaries`, not ambiguous `target/release` basenames. No extra binary, omitted service, duplicate output path, traversal, symlink, empty file or modified selected Git-pinned input is accepted. The CLI compares selected tracked input bytes with their pinned Git tree blobs, rejects untracked generated service-client and SDK files, inventories **all** files in both generated WASM packages and the entire production dist, verifies one emitted WASM per package equals generated bytes, validates the single raw cache/Brotli pair, checks executable binary bits, and checks bundle metadata and semver against the commit and web package version. Each result records a stable group-relative path, byte count and SHA-256; `digest` hashes the single-line JSON serialization of `{schemaVersion,sourceSha,binaries,files}` followed by LF, using the displayed property order. The manifest itself contains no machine path, timestamp or secrets. `--verify` rechecks a previously collected manifest and its canonical digest to detect post-capture tampering. `--output` creates a new file with mode 0600 and refuses to overwrite existing evidence.

The collector does **not** certify that any binary has the intended target architecture or complete native runtime-library/asset closure; verify those separately (e.g. `file`, dynamic linker inspection and Nix closure on the target OS). Git-pinned generated code presence and hashes are not a regeneration check; run the generators in a disposable copy and compare the result with tracked source. The existing bundle manifest records SHA/version/build numbers but not the actual `MODE` environment; the CLI checks `/app` production entrypoint and build metadata, while an independently captured `MODE=production NODE_ENV=production` command log is still required to prove build mode. One run proves observed bytes, **not** cross-run byte reproducibility. A newly captured manifest has no external artifact hash oracle until independently saved and rechecked.
