# CTN upstream sync (RUS-1507)

## Boundaries

The canonical source is `tooling/scripts/sync-upstream.sh`; the installed host entry point is `/Users/t/Projects/CTN/.fusion/sync-upstream.sh`. Production execution always selects `/Users/t/Projects/CTN` on `main`, regardless of the caller's working directory. The only override is `SYNC_UPSTREAM_FIXTURE=1 ... --fixture-root /absolute/disposable/repo`; it rejects the live checkout and any nonlocal fixture upstream URL. The script fetches only the configured `upstream` URL's `refs/heads/main` into a disposable ref, verifies it against the previously retained `refs/remotes/upstream/main`, then CAS-updates that tracking ref only for accepted history. It does not fetch tags, prune, fetch origin, or push. Production requires the configured fetch URL `https://github.com/macro-inc/macro.git`; it never creates a missing remote.

This is **upstream convergence**, not the RUS-1508 direct-main-merge gate. Its `backup/upstream-sync-*` refs protect only runs of this script. A direct Git update does not call this script; the separate installed reference-transaction hook owns `backup/pre-merge-*` refs. Never weaken, replace, or bypass that hook to make a divergent rebase succeed.

## Safety sequence

1. Resolve the physical root and check active branch `main`, non-shallow history, index/worktree cleanliness (including untracked paths), and no merge/rebase/cherry-pick/revert/sequencer operation **before fetch**. Require the effective executable `reference-transaction` hook to match the tracked `tooling/scripts/ctn_main_ref_gate.py` byte-for-byte; refuse a custom `core.hooksPath`. Acquire an atomic directory lock in Git's common directory. A held or stale lock is a refusal, not an invitation to delete it blindly.
2. Fetch the one explicit upstream ref into a one-use ref without mutating the saved tracking checkpoint. Recheck root status and captured main. Reject upstream ref rewinds relative to the previously known remote-tracking tip; a rejected fetch leaves that tip unchanged, including across repeated runs. CAS-update tracking only after validation. Equal and local-ahead runs report no main rewrite and make no sync backup.
3. On behind/divergent history, capture the exact old main OID. Create `refs/heads/backup/upstream-sync-<UTC>-<random>` with `git update-ref <name> <old> <all-zero-old>`, forcing ref fsync. Retry a *name collision* with a new name; abort on other creation errors. Read the backup back and verify main is still old. Ask the installed gate to reserve its independent `backup/pre-merge-*` ref of the same old OID and read it back. **Both backups precede any candidate worktree or rebase**. Neither backup is removed on success, failure, or repeat.
4. Behind: candidate is fetched upstream tip (old is already its ancestor). Divergent: detach a temporary worktree at old, rebase local commits on upstream with `--rebase-merges`, and stop on a real conflict; live main/index/worktree remain unchanged and the old backup remains. A successful rebase normally discards old ancestry, which the installed gate prohibits. Construct a provenance bridge merge whose first parent is the rebased tip and second parent is exact old main, with the **same tree** as the rebased tip. Verify both old and fetched upstream are ancestors. The bridge does not silently resolve conflicts or alter the rebased content. Old local commits remain reachable through its second parent even when Git skips patch-equivalent commits. Complex criss-cross histories with multiple merge bases fail closed rather than selecting an arbitrary replay base.
5. Recheck branch, operations, all dirt, old main and fetched tracking ref. Git's `update-ref refs/heads/main <candidate> <old>` performs expected-old CAS through the installed hook with the previously verified gate reservation. A concurrent writer makes this fail or triggers the fresh-state refusal. Only after CAS does a two-tree `read-tree -m -u <old> <candidate>` update the root index and worktree; it refuses late edits rather than resetting them. A post-CAS checkout refusal is a **nonzero, human-recovery condition**, not a reason to force-reset or silently roll main back. Retained refs and the error report contain old, candidate and backup identifiers.

The lock serializes this script's instances, not arbitrary Git writers. CAS and the installed hook enforce the ref boundary; no shell-level status check makes the entire checkout/ref/index transition atomic. Signals attempt to clean the script's temporary worktree and release its own lock. A process killed without trap execution can leave a stale lock: inspect process ownership, candidate worktree and backups before removing only that stale lock. A persistent failed temporary worktree is explicitly named on stderr.

## Fixture and operator workflow

The offline `bash tooling/scripts/test-sync-upstream.sh` suite creates disposable local repos with an independent bare upstream and bare origin. It copies the tracked gate into the fixture and activates a byte-identical reference-transaction hook; calls the **real canonical entry point** only in fixture mode; and checks equal/ahead no-op, behind, divergence/bridge, exact-old pre-candidate backup observation, repeat/retention, dirty staged/unstaged/untracked, in-progress operation, lock contention, failing local upstream, rejected rewind and its repeated refusal without tracking-ref poisoning, backup collision, genuine conflict, deterministic main race, remote no-push and negative direct-main isolation. Fixture-only callbacks run after backup or before CAS; they cannot run against the production root. Do not substitute this for a live-main test.

Before deploying, run that fixture suite and applicable syntax/changed-file checks; review any failures. With the existing Fusion routine **disabled**, preserve the currently installed script separately, install the reviewed tested source atomically to the root `.fusion/sync-upstream.sh` with executable permissions, and read back its hash, shebang and permissions. Confirm the installed main gate and exact scheduler identity, user, working directory, environment, timezone, command, cron, enabled state, and latest run/error through the supported Fusion interface. Do not create another cron/procedure. Only the operator responsible for live integration can decide when to re-enable and read back the original routine; no local fixture proves a historical scheduled execution. Do not run a live sync while the root is dirty.

On failure, record stderr and the old/candidate/backup OIDs; stop the routine until inspected. For a rebase conflict, main is untouched: fix the underlying conflicting changes on a separate branch and retry only after reviewing the root state. For recoverability, inspect `git show <backup>` and `git diff <backup> main`; create a **new recovery branch/worktree** from the retained backup if necessary. Do not delete an old backup, force-push, reset the live root or roll main back through the protected hook. If CAS succeeded but checkout refused, inspect main, index, root dirt and retained backup before manually reconciling; avoid a second scheduled invocation until resolved.
